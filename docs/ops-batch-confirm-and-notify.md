# 확인 필요 일괄 확인 · 운영자 알림

부스 운영 현황의 **관리 조치** 칸에 있는 ‘일괄 확인 · 운영자 알림’ 의 설계입니다.

| | 상태 |
|---|---|
| 일괄 확인 | **구현됨 · Production 미적용.** 적용 SQL `supabase/migration-booth-live-check.sql` · 되돌리기 `supabase/rollback-booth-live-check.sql` · 관리자 화면. 함수가 없는 동안(지금 Production) 화면은 ‘준비 중’ 그대로입니다. Production 적용은 운영 담당자가 직접 합니다. |
| 운영자 알림 | 설계만(아래 3장). 누를 수 없는 ‘준비 중’. |

## 2. 확인 필요 일괄 확인

### 원칙
- 관리자가 **실제로 확인한 부스만** 고릅니다. 처음에는 **모두 비어 있고**, 자동 선택 · 전체 자동 확인은 없습니다.
- **관리자 확인 ≠ 운영자 입력.** 확인은 관리자 화면의 ‘확인 필요’ 를 정리하는 **별도 기록**이고, 현황 값과 그 시각(`booth_live`)은 건드리지 않습니다.
  관람객에게 보이는 값을 바꾸려면 지금처럼 [수정](`admin_set_booth_live`, 기록 `admin`)으로 **값을 입력**합니다.
- 미리보기 뒤에 다른 운영자 · 관리자가 그 부스를 바꿨으면 **자동으로 제외**합니다.
- 결과는 **확인 완료 · 제외 · 실패** 로 나눠 보여 주고, 누가 · 언제 · 어떤 값을 확인했는지 남깁니다.

### `updated_at` 을 옮기는 방식은 쓰지 않습니다(검토 결과)
처음 설계(운영자 ‘변동 없음 · 지금 확인’ 처럼 `booth_live.updated_at` 만 지금으로)는 실제 운영 기록을 왜곡합니다.

| 어디 | `updated_at` 을 옮기면 |
|---|---|
| 관람객 화면 | `booth-core.js` `bucket()` 은 30분 넘은 값을 ‘정보 없음’ 으로 숨깁니다. 관리자가 시각을 옮기면 **아무도 새로 입력하지 않은 값이 다시 ‘지금 값’ 으로 공개**됩니다 — 금지한 ‘오래된 상태 → 최신 상태 자동 전환’ 과 같습니다. |
| 운영자 화면 | ‘마지막 입력 N분 전’ 과 20분 확인 상자(nudge)가 다시 0분부터 셉니다 — 현장 운영자가 확인 요청을 못 받습니다. |
| 기록 · 사후 분석 | `updated_at` = ‘현장(운영자)이 마지막으로 확인한 때’ 라는 뜻이 섞입니다. 로그로 가를 수는 있지만 화면 · 통계가 모두 `updated_at` 을 씁니다. |
| 23:00 초기화 · 공통 PIN | 영향 없음(어느 방식이든). |

운영자의 ‘변동 없음 · 지금 확인’ 이 `updated_at` 을 옮기는 것은 그대로 둡니다 — 현장에서 본 사람이 누르는 것이라 왜곡이 아닙니다.

### DB — 새 테이블 1 · 새 함수 2만, 기존 것은 그대로 (`supabase/migration-booth-live-check.sql`)
1. `booth_live_check` — `id` · `batch_id` · `booth_id` · **`seen_updated_at`**(확인한 값의 입력 시각) · `seen_congestion` · `seen_wait` · `checked_by`(`auth.uid()`) · `checked_at`.
   RLS 켬 · 정책 없음 · anon/authenticated 표 권한 없음(함수로만). 지우지 않고 쌓기만 합니다(감사 기록).
   `booth_live` · `booth_live_log` · 기존 함수 · 정책 · 23:00 예약 작업은 바꾸지 않습니다.
2. `public.admin_confirm_booth_live(p_items jsonb)` — security definer · `search_path = ''` · `lock_timeout = 3s`.
   anon 실행 권한 없음, authenticated 는 실행할 수 있지만 함수 안 `is_admin()` 이 아니면 42501.
   - 입력: `[{ booth_id, seen_updated_at }]`(미리보기에서 본 마지막 입력 시각) 1~100개. 형식이 하나라도 틀리면 통째로 거절(22023, 아무것도 기록 안 함).
   - **booth_id 순서로** 부스마다 `booth_live` 줄을 **`FOR UPDATE`** 로 잠근 뒤 판단(부스마다 예외 블록 — 한 부스 오류가 나머지를 막지 않음):
     | 상황 | 결과 |
     |---|---|
     | 같은 요청 안에 같은 부스가 또 | `skipped:duplicate`(처음 것만 처리) |
     | 그런 부스 없음 · 값 없음 | `skipped:not_found` · `skipped:no_value`(미입력 · 23:00 초기화 뒤) |
     | 오늘(KST) 값 아님 | `skipped:not_today` |
     | 마감 | `skipped:closed` |
     | `updated_at <> seen_updated_at` | `skipped:changed` — 미리보기 뒤 운영자(QR · PIN) · 관리자가 입력함 |
     | 30분 안에 입력됨 | `skipped:fresh` |
     | 같은 값을 30분 안에 이미 관리자 확인함 | `skipped:checked`(그 확인 시각을 돌려줌) — 같은 요청 두 번 · 다른 관리자 |
     | 그 밖 | `booth_live_check` 한 줄 → `confirmed` |
     | 3초 안에 못 잠금 · 그 밖 오류 | 그 부스만 `failed:busy` · `failed` |
   - 돌려주는 값: 부스마다 `(booth_id, status, checked_at, live_updated_at, batch_id)`.
3. `public.admin_booth_live_checks()` — 관리자 읽기. 부스마다 **지금 값과 `seen_updated_at` 이 같은** 오늘(KST)의 마지막 확인(누가 · 언제 · 나인지).
   운영자가 새로 입력하면 `updated_at` 이 바뀌어 그 확인은 저절로 빠집니다(기록은 남음).
4. 되돌리기 `supabase/rollback-booth-live-check.sql`: 두 함수만 drop. 기록 표는 남김(아무도 읽거나 쓰지 못함). 다시 적용하면 이어 씀.

### 동시성 — `FOR SHARE` 로는 중복 확인을 못 막습니다
- `FOR SHARE` 는 공유 잠금끼리 서로 막지 않습니다. 두 관리자(또는 두 번 누른 같은 요청)가 같은 부스를 동시에 잡으면 둘 다 ‘아직 확인 없음’ 을 보고 둘 다 기록합니다.
  운영자 입력(UPDATE)은 막지만 관리자끼리는 못 막습니다.
- `FOR UPDATE` 는 관리자끼리 · 운영자 입력(`booth_ctrl_set` · `touch`, `booth_session_*`, `admin_set_booth_live`) · 23:00 초기화(delete) 모두와 차례를 지킵니다.
  뒤에 온 쪽은 앞 쪽이 끝날 때까지 기다린 뒤 READ COMMITTED 에서 그 줄의 최신 판을 다시 읽고, ‘이미 확인했는가’ 도 새 스냅숏으로 봅니다
  → 늦은 관리자는 `skipped:checked`, 그 사이 운영자가 입력했으면 `skipped:changed`.
- 잠그기만 하고 값 · 시각은 바꾸지 않습니다. 운영자 입력은 관리자 요청이 끝날 때까지만(보통 수 ms) 기다립니다.
- booth_id 순서로 잠가 두 관리자 묶음이 엇갈려 잠그는 교착을 막고, `lock_timeout 3s` 로 오래 걸리는 입력이 있으면 그 부스만 `failed:busy` 로 넘깁니다.
- 남는 위험(낮음): 23:00 초기화는 84곳을 순서 없이 지웁니다. 그 순간 일괄 확인이 겹치면 PostgreSQL 이 1초 뒤 교착을 풀며 한쪽을 실패시킵니다
  (관리자 쪽이면 그 부스만 `failed`, 초기화 쪽이면 그날 리허설 초기화가 한 번 빠짐). 23:00 은 운영 시간 밖이고 리허설 초기화는 11-05 까지입니다.

### 관리자 화면에서의 뜻
- **‘확인 필요’(30분 넘게 그대로) 판정 · 표시 · 수는 그대로**입니다. 관리 조치 ‘확인 필요 N곳’ · 운영 상태 칸의 점선 ‘확인 필요 ○’ 도 줄지 않습니다.
- 관리자 확인은 그 위에 **따로** 붙습니다: 줄의 ‘확인 필요’ 옆 ‘관리자 확인 14:20’(자세히: 누가 · 언제 · ‘현황 값 · 입력 시각은 그대로’), 관리 조치 설명 줄의 ‘관리자 확인 n’.
  확인한 지 30분이 지나거나 운영자가 새로 입력하면 저절로 사라집니다.
- 관람객 · 운영자 화면은 그대로입니다(관람객에게는 여전히 30분 넘은 값 = ‘정보 없음’). 공개 값까지 새로 하려면 [수정]으로 입력합니다.

`admin_set_booth_live` 를 여러 번 부르는 방식도 **쓰지 않습니다** — ‘관리자가 값을 입력함’ 과 구분되지 않고, 막 바뀐 값을 덮을 수 있습니다.

### 화면 흐름(구현됨)
1. 관리 조치 **[일괄 확인]**(함수가 있을 때만 누를 수 있음) → 부스 목록이 ‘확인 필요’ 로 걸러지고, 아직 확인 안 한 줄에만 체크칸(모두 비어 있음). 이미 확인한 줄은 ‘확인함’.
2. 붙박이 도구 줄의 고르기 줄: ‘고른 N곳’ · 구역 단위로 모두 고르기(R1~R4, 그 구역의 확인 필요 수) · 선택 비우기 · 미리보기 · 끝내기.
   고른 뒤 새로 입력되거나 다른 관리자가 확인한 부스는 15초 새로 읽기 때 저절로 빠지고 몇 곳 빠졌는지 보입니다.
3. **미리보기** — 고른 부스의 번호 · 이름 · 마지막 상태 · 대기 · 마지막 입력 시각 · 입력 주체, 부스마다 [빼기].
   ‘관리자 확인 기록만 남습니다. 관람객 화면 값과 운영자 입력 시각은 바뀌지 않습니다.’ 그 사이 새 입력이 온 부스는 ‘보내도 제외됩니다’.
4. **[확인 기록 남기기 (N곳)]** → 결과: **확인 완료 N** · **제외 N**(부스별 까닭) · **실패 N**(실패만 다시 시도 — 같은 미리보기 값으로).
   응답을 못 받으면 그렇다고 쓰고, 다시 보내도 같은 값은 한 번만 기록된다고 알립니다.
5. 함수가 없으면(PGRST202 — 적용 전 · 되돌린 뒤) 단추는 ‘준비 중’, 협의용 예시(?demo)도 ‘준비 중’.

## 3. 운영자 알림

### 방식 비교

| | ① 화면 내부 알림 | ② 서버 폴링 알림 | ③ 웹 PUSH |
|---|---|---|---|
| 뜻 | 운영자 화면이 다음에 그려질 때 띠로 보임 | 운영자 화면이 열려 있는 동안 주기적으로 새 알림을 묻고, 오면 띠 + 소리 · 진동 | 브라우저 · 휴대폰 알림(화면을 닫아도) |
| 언제 닿나 | 화면이 열려 있고 보일 때, 다음 갱신(최대 60초) | 화면이 보일 때 15~20초 안. 화면이 꺼지면 휴대폰이 멈춰 다시 켤 때 | 휴대폰 잠김 · 브라우저 닫힘에도(보통 수 초) |
| 필요한 것 | 알림 테이블 · 운영자용 읽기/확인 함수 · 운영자 화면 수정 | ① + 알림 확인 주기만 짧게 | ① + 서비스 워커 · manifest · 알림 권한 · 구독 저장 · VAPID 열쇠 · 발송 서버(Edge Function) |
| iPhone | 됨 | 됨 | iOS 16.4 이상 + **홈 화면에 추가한 경우에만** |
| 비용 | DB 읽기 조금(84곳 × 분당 1번) | DB 읽기 조금 더(분당 3~4번) | 발송 서비스는 무료(브라우저 회사 푸시 서버), Edge Function 무료 한도 안. 구현 · 시험 시간이 큼 |
| 위험 | 낮음 | 낮음 | 서비스 워커 캐시 오류가 행사 중 운영자 화면을 망가뜨릴 수 있음, 권한 거부 · 구독 만료 |

**권장**: 행사(11-06 · 07)에는 **② 서버 폴링 알림(① 포함)** 만. ③ 웹 PUSH 는 행사 뒤 또는 리허설에서 안드로이드 · 홈 화면 설치 운영자로 따로 시험한 뒤 결정.
(문자 · 알림톡은 운영자 전화번호 수집 · 발신 등록 · 건당 비용이 들어 이번 범위에서 뺍니다.)

### 데이터 (승인 필요, ① · ② 공통)
- `booth_notice` — `id` · `kind`(`stale` · `missing` · `zone` · `all`) · `body`(120자 안) · `created_by uuid` · `created_at` · `expires_at`(기본 그날 운영 끝).
- `booth_notice_target` — `(notice_id, booth_id)` PK · `shown_at`(운영자 화면에 **실제로 그려진** 때) · `acked_at`(운영자가 ‘확인했어요’ 누른 때) · `acked_session uuid null`.
- RLS 켜고 정책 없음(함수로만).
- 관리자 함수 `admin_send_booth_notice(p_kind, p_zone, p_booth_ids, p_body)`:
  - 대상은 **보낼 때 서버가 다시 계산**(확인 필요 = 같은 30분 규칙, 미입력 = 오늘 값 없음, 구역 = 공개 부스, 전체 = 공개 부스).
  - 반복 발송 방지: 같은 부스에 같은 종류를 **10분 안에 다시 보내지 않음**(`skipped:recent`), 전체 공지는 5분에 한 번.
  - 돌려주는 값: 부스마다 `queued` · `skipped:recent` · `skipped:not_target`.
- 운영자 함수(QR 열쇠 · PIN 세션으로 확인): `booth_ctrl_notices(p_token)` / `booth_session_notices(p_session)` — 그 부스의 만료 전 · 미확인 알림.
  `..._notice_shown(id)` — 화면이 보이는 상태에서 띠를 그린 뒤에만. `..._notice_ack(id)` — ‘확인했어요’ 를 눌렀을 때만.
  - **자기 부스만**: 운영자 함수는 `booth_id` 를 받지 않습니다. 부스는 서버가 열쇠 · 세션에서 정하고(기존 `booth_ctrl_*` · `booth_session_*` 와 같은 확인 — 꺼진 QR · 끝난 세션 · 공통 PIN 기간 끝은 거절),
    다른 부스의 알림 id 를 넣으면 ‘없음’ 과 똑같이 답합니다(있는지조차 알 수 없게).
  - shown · ack 함수는 `booth_notice_target` 의 시각 칸만 씁니다. **`booth_live` · `booth_live_log` 는 쓰지 않습니다**(알림 확인으로 혼잡도 · 대기 · 입력 시각이 바뀌지 않음).
- 관리자 읽기 `admin_booth_notice_status(p_notice_id)` — 부스마다 대기 · 표시됨 · 확인함.

### 정직한 상태 표시
- 관리자 화면 상태는 **대기(아직 화면에 안 뜸) · 화면에 표시됨 · 운영자 확인** 셋뿐입니다. ‘전달 완료’ 라고 쓰지 않습니다.
- 표시 · 확인은 운영자 화면이 **보이는 상태에서 실제로 그리고 / 누른 뒤에만** 기록합니다. 자동으로 읽음 처리하지 않습니다.
- ③ 웹 PUSH 를 더하면 푸시 서버가 받은 것(201)은 ‘발송 요청 접수’ 로만 쓰고, 404 · 410 은 구독 끊김으로 표시 · 정리, 429 · 5xx 는 몇 번 다시 시도한 뒤 ‘발송 실패’.
- 알림 확인은 현황 값과 별개입니다. 운영자가 ‘확인했어요’ 를 눌러도 `booth_live` 는 바뀌지 않습니다.
  띠 옆에 기존 ‘변동 없음 · 지금 확인’ 단추를 **따로** 두어 운영자가 원하면 누르게 할 뿐, 한 단추로 둘을 함께 하지 않습니다.

### 화면 흐름
- 관리자: 관리 조치 **[운영자 알림]** → 대상 고르기(확인 필요 N곳 · 미입력 N곳 · 구역 · 전체 공지) → 문구(틀 + 120자) → **미리보기**(받을 부스 목록, 10분 안에 받은 부스는 ‘제외 · 최근 받음’) → [보내기] → 결과(보냄 N · 제외 N) → 부스별 대기 · 표시됨 · 확인 상태(15초마다 갱신).
- 운영자 화면: 위쪽 띠 ‘관리자 알림 · 14:20 · 상태를 다시 확인해 주세요’ + [변동 없음 · 지금 확인] · [확인했어요]. 여러 개면 최신 하나 + ‘이전 알림 2’.

### 바뀌는 곳
- main(GitHub Pages): 관리자 화면(booth-admin) — 보내기 · 상태.
- **booth-live(Vercel)**: 운영자 화면(booth-ctrl) — 알림 띠 · 짧은 알림 확인 주기. 별도 승인 · 배포가 필요합니다.
- 되돌리기: 함수 · 테이블 drop SQL. 함수가 없으면(PGRST202) 두 화면 모두 알림 기능을 숨깁니다.
