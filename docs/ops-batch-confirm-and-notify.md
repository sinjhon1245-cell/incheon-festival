# 확인 필요 일괄 확인 · 운영자 알림 — 설계(미구현)

부스 운영 현황의 **관리 조치** 칸에 있는 ‘일괄 확인 · 운영자 알림 — 준비 중’의 설계입니다.
지금은 화면에 **누를 수 없는 ‘준비 중’** 으로만 있고, DB 함수 · 테이블 · 발송 기능은 없습니다.
아래 SQL · 화면 변경은 승인 뒤 별도 PR로 만들고, Production 적용은 운영 담당자가 직접 합니다.

---

## 1. 지금 구조(조사 결과)

| 항목 | 지금 |
|---|---|
| 현황 값 | `booth_live` — `booth_id`(PK) · `congestion` · `wait_minutes` · `updated_at` 하나. 쓰기는 모두 security definer 함수 |
| 기록 | `booth_live_log` — `source` 는 `set` · `touch` · `admin` 셋, `session_id`(PIN 세션). **관리자 id 칸 없음**, 읽기 정책 없음(SQL Editor 전용) |
| ‘변동 없음 · 지금 확인’ | `booth_ctrl_touch(p_token)`(QR) · `booth_session_touch(p_session)`(PIN) — 같은 날(KST) 값이 있을 때 `updated_at` 만 지금으로, 로그 `touch` |
| 관리자 수정 | `admin_set_booth_live` — 값을 **다시 저장**(upsert)하고 로그 `admin`. 시각만 옮기는 방법 없음 |
| 입력 주체 표시 | `admin_booth_credentials().live_by` = 마지막 로그로 계산(`admin` → 관리자, `session_id` 있음 → PIN, 그 밖 → QR) |
| 운영자 로그인 | QR = 주소 `#k=` 열쇠(브라우저 저장), PIN = 세션 열쇠(브라우저 저장, 로그인 뒤 12시간 또는 그날 자정에 끝남) |
| 운영자 화면 갱신 | 60초(±20%) 폴링 · 화면이 가려져 있으면 건너뜀 · 다시 보이면 0~3초 안에 읽음. Realtime 안 씀 |
| 알림 장치 | 서비스 워커 · 웹 앱 manifest · Notification API · Push · Edge Function **모두 없음**. 화면 안 토스트 · 20분 넘으면 ‘맞아요’ 확인 상자(nudge)만 있음 |
| 공지 테이블 | `notices` 는 기본 포털 공지판(부스 지정 없음) — 운영자 화면은 읽지 않음 |

## 2. 확인 필요 일괄 확인

### 원칙
- 관리자가 **실제로 확인한 부스만** 고릅니다. 처음에는 **모두 비어 있고**, 자동 선택 · 전체 자동 확인은 없습니다.
- 값(혼잡도 · 대기)은 **다시 저장하지 않고**, 확인 시각만 지금으로 옮깁니다(운영자 ‘변동 없음 · 지금 확인’ 과 같은 효과).
- 미리보기 뒤에 다른 운영자 · 관리자가 그 부스를 바꾸거나 확인했으면 **자동으로 제외**합니다.
- 결과는 **확인 완료 · 제외 · 실패** 로 나눠 보여 주고, 누가 언제 확인했는지 기록을 남깁니다.

### DB (승인 필요)
1. `booth_live_log.source` 제약에 `'admin_touch'` 추가.
2. `booth_live_log` 에 `actor_id uuid null`(확인한 관리자) · `batch_id uuid null`(한 번에 보낸 묶음) 칸 추가 — 기존 줄은 null.
3. 새 함수 `public.admin_confirm_booth_live(p_items jsonb)` — security definer · `is_admin()` · anon 실행 불가.
   - 입력: `[{ booth_id, seen_updated_at }]`(미리보기에서 본 마지막 입력 시각), 1~84개, 중복 제거.
   - 부스마다 `for update` 로 잠그고:
     | 상황 | 결과 |
     |---|---|
     | 값 없음 | `skipped:no_value` |
     | 오늘(KST) 값 아님 | `skipped:not_today` |
     | 마감 | `skipped:closed` |
     | 30분 안에 이미 갱신됨 | `skipped:fresh` |
     | `updated_at <> seen_updated_at` | `skipped:changed` — 그 사이 누가 바꿈/확인함 |
     | 그 밖 | `updated_at = now()` 만 바꾸고 로그 `admin_touch` + `actor_id` + `batch_id` → `confirmed` |
     | 함수 안 오류 | 그 부스만 `failed`(나머지는 계속) |
   - 돌려주는 값: 부스마다 `(booth_id, status, updated_at)`.
4. `admin_booth_credentials()` 의 `live_by` 에 `admin_touch → 'admin_check'`(화면 ‘관리자 확인’) 추가 — 안 하면 ‘운영자 QR’ 로 잘못 보입니다.
5. 되돌리기 SQL: 함수 drop · grant 회수 · `live_by` 원복 · 제약 원복. 추가한 칸은 남겨도 무해. 이미 옮긴 확인 시각은 값이 그대로라 되돌릴 데이터가 없습니다.

`admin_set_booth_live` 를 여러 번 부르는 방식은 **쓰지 않습니다** — ‘관리자가 값을 바꿈’과 구분되지 않고, 막 바뀐 값을 덮을 수 있습니다.

### 화면 흐름
1. 관리 조치 **[일괄 확인]** → 부스 목록이 ‘확인 필요’ 로 걸러지고, 그 줄에만 체크칸이 생깁니다(모두 비어 있음).
2. 위쪽 줄: **구역 고르기**(R1~R4) · ‘이 구역의 확인 필요 모두 고르기’ · ‘선택 비우기’ · ‘N곳 선택’.
3. **[미리보기]** — 고른 부스의 번호 · 이름 · 마지막 상태 · 대기 · 마지막 입력 시각 · 입력 주체.
   ‘N곳의 확인 시각만 지금으로 바뀝니다. 값은 그대로입니다. 현장에서 확인한 부스만 남기세요.’ 상태가 다른 부스는 여기서 빼고 [수정]으로 고칩니다.
4. **[확인 시각 갱신]** → 결과: **확인 완료 N** · **제외 N**(바뀜 · 이미 최신 · 값 없음 · 마감, 부스별 까닭) · **실패 N**(실패만 다시 시도).
5. 함수가 없으면(PGRST202) 단추는 지금처럼 ‘준비 중’ 으로 남습니다.

## 3. 운영자 알림

### 방식 비교

| | ① 화면 내부 알림 | ② 서버 폴링 알림 | ③ 웹 PUSH |
|---|---|---|---|
| 뜻 | 운영자 화면이 다음에 그려질 때 띠로 보임 | 운영자 화면이 열려 있는 동안 주기적으로 새 알림을 묻고, 오면 띠 + 소리 · 진동 | 브라우저 · 휴대폰 알림(화면을 닫아도) |
| 언제 닿나 | 화면이 열려 있고 보일 때, 다음 갱신(최대 60초) | 화면이 보일 때 15~20초 안. 화면이 꺼지면 휴대폰이 멈춰 다시 켤 때 | 휴대폰 잠김 · 브라우저 닫힘에도(보통 수 초) |
| 필요한 것 | 알림 테이블 · 운영자용 읽기/확인 함수 · 운영자 화면 수정 | ① + 알림 확인 주기만 짧게 | ① + 서비스 워커 · manifest · 알림 권한 · 구독 저장 · VAPID 열쇠 · 발송 서버(Edge Function) |
| iPhone | 됨 | 됨 | iOS 16.4 이상 + **홈 화면에 추가한 경우에만** |
| 비용 | DB 읽기 조금(84곳 × 분당 1번) | DB 읽기 조금 더(분당 3~4번) | 발송 서비스는 무료(브라우저 회사 푸시 서버), Edge Function 무료 한도 안. 구현 · 시험 시간이 큼 |
| 위험 | 낮음 | 낮음 | 서비스 워커 캐시 오류가 행사 중 운영자 화면을 망가뜨릴 수 있음, 권한 거부 · 구독 만료 |

**권장**: 행사(11-06 · 07)에는 **② 서버 폴링 알림(① 포함)** 만. ③ 웹 PUSH 는 행사 뒤 또는 리허설에서 안드로이드 · 홈 화면 설치 운영자로 따로 시험한 뒤 결정.
(문자 · 알림톡은 운영자 전화번호 수집 · 발신 등록 · 건당 비용이 들어 이번 범위에서 뺍니다.)

### 데이터 (승인 필요, ① · ② 공통)
- `booth_notice` — `id` · `kind`(`stale` · `missing` · `zone` · `all`) · `body`(120자 안) · `created_by uuid` · `created_at` · `expires_at`(기본 그날 운영 끝).
- `booth_notice_target` — `(notice_id, booth_id)` PK · `shown_at`(운영자 화면에 **실제로 그려진** 때) · `acked_at`(운영자가 ‘확인했어요’ 누른 때) · `acked_session uuid null`.
- RLS 켜고 정책 없음(함수로만).
- 관리자 함수 `admin_send_booth_notice(p_kind, p_zone, p_booth_ids, p_body)`:
  - 대상은 **보낼 때 서버가 다시 계산**(확인 필요 = 같은 30분 규칙, 미입력 = 오늘 값 없음, 구역 = 공개 부스, 전체 = 공개 부스).
  - 반복 발송 방지: 같은 부스에 같은 종류를 **10분 안에 다시 보내지 않음**(`skipped:recent`), 전체 공지는 5분에 한 번.
  - 돌려주는 값: 부스마다 `queued` · `skipped:recent` · `skipped:not_target`.
- 운영자 함수(QR 열쇠 · PIN 세션으로 확인): `booth_ctrl_notices(p_token)` / `booth_session_notices(p_session)` — 그 부스의 만료 전 · 미확인 알림.
  `..._notice_shown(id)` — 화면이 보이는 상태에서 띠를 그린 뒤에만. `..._notice_ack(id)` — ‘확인했어요’ 를 눌렀을 때만.
- 관리자 읽기 `admin_booth_notice_status(p_notice_id)` — 부스마다 대기 · 표시됨 · 확인함.

### 정직한 상태 표시
- 관리자 화면 상태는 **대기(아직 화면에 안 뜸) · 화면에 표시됨 · 운영자 확인** 셋뿐입니다. ‘전달 완료’ 라고 쓰지 않습니다.
- 표시 · 확인은 운영자 화면이 **보이는 상태에서 실제로 그리고 / 누른 뒤에만** 기록합니다. 자동으로 읽음 처리하지 않습니다.
- ③ 웹 PUSH 를 더하면 푸시 서버가 받은 것(201)은 ‘발송 요청 접수’ 로만 쓰고, 404 · 410 은 구독 끊김으로 표시 · 정리, 429 · 5xx 는 몇 번 다시 시도한 뒤 ‘발송 실패’.
- 알림 확인은 현황 값과 별개입니다. 운영자가 ‘확인했어요’ 를 눌러도 `booth_live` 는 바뀌지 않고, 띠에서 바로 ‘변동 없음 · 지금 확인’ 또는 현황 입력으로 이어지게 합니다.

### 화면 흐름
- 관리자: 관리 조치 **[운영자 알림]** → 대상 고르기(확인 필요 N곳 · 미입력 N곳 · 구역 · 전체 공지) → 문구(틀 + 120자) → **미리보기**(받을 부스 목록, 10분 안에 받은 부스는 ‘제외 · 최근 받음’) → [보내기] → 결과(보냄 N · 제외 N) → 부스별 대기 · 표시됨 · 확인 상태(15초마다 갱신).
- 운영자 화면: 위쪽 띠 ‘관리자 알림 · 14:20 · 상태를 다시 확인해 주세요’ + [변동 없음 · 지금 확인] · [확인했어요]. 여러 개면 최신 하나 + ‘이전 알림 2’.

### 바뀌는 곳
- main(GitHub Pages): 관리자 화면(booth-admin) — 보내기 · 상태.
- **booth-live(Vercel)**: 운영자 화면(booth-ctrl) — 알림 띠 · 짧은 알림 확인 주기. 별도 승인 · 배포가 필요합니다.
- 되돌리기: 함수 · 테이블 drop SQL. 함수가 없으면(PGRST202) 두 화면 모두 알림 기능을 숨깁니다.

## 4. 구현 순서(승인 뒤)
1. 일괄 확인 SQL(적용 · 되돌리기) + 복제 DB 시험(동시 수정 · 권한 · anon 차단 · 결과 구분) → 관리자 화면 PR.
2. 알림 SQL + 복제 DB 시험(대상 계산 · 반복 방지 · 표시/확인 기록 · 권한) → 관리자 화면 PR + 운영자 화면 PR(booth-live).
3. 리허설에서 운영자 몇 곳으로 시험 → 행사 적용 여부 결정.
