## 최종 목표와 현재 상태(2026-11-04 읽기 전용 재검증)
- 학교 84곳(초29, 중25, 특1, 고29)과 체험존 12곳(게임4, 교육8)은 현재 공개 상태. 미래채움존은 0곳.
- 기존 학교 84·체험 12의 UUID/번호/명칭/기관/QR/PIN/상태/기록 보존.
- 미래채움존 9곳을 별도 zone_key=`미래`로 등록, code=`미래1`~`미래9` 사용.

- 미래·체험 탭 안의 구역은 미래채움존 9곳 → 체험존 12곳 순서로 제목을 나눠 표시. 미래채움존을 공개하기 전에는 체험존 칸만 보입니다. 운영자에서 각자 독립 PIN/QR 사용.

## 안전 적용 순서(미래존 전용)
1. PR #68 코드 및 새 96→105용 SQL 격리 검증(`test-db-105.mjs`). 320/360/375/390/414/768/1024/1440px 확인(5개 탭 넘침 · 구역 분리 · 세로 가운데 · 검색).
2. UI 병합 → Vercel Production READY → **96곳 그대로**, 5개 탭(체험존 칸)과 체험존 보존 확인.
3. `check-booth-105.sql` 읽기 전용 사전 지문 확보, 이상 시 STOP.
4. `migration-booth-future-after-experience.sql`: 미래 9곳 비공개 등록, 기존 번호 트리거 및 23시 초기화에 *미래를 추가*하되 체험 유지. 당일 상태와 QR/PIN/이력 보존.
5. 9곳 QR/PIN 발급 → 카드 인쇄 → 실제 기기로 1곳 테스트. 비공개 상태에서 인증이 거절되는 것은 정상.
6. `publish-booth-future-after-experience.sql`: QR/PIN 9/9 확인 후 공개. 관람객 105 / 5개 탭 / 미래1~9 / 체험1~12 확인.
7. 한 부스 테스트 값을 삭제하고 23:00 초기화가 학교84+체험12+미래9를 포함하는지 검증.
8. 문제 시 `rollback-booth-future-after-experience.sql`로 미래 9곳만 숨김(96곳 복귀; QR/PIN은 유지). 공개 화면을 과거 84곳 버전으로 롤백하지 말 것.
