# 미래채움존 9곳 + 체험존 12곳 병행 운영: 검증 체크리스트

## 목적
- 기존 학교 84곳 / 체험존 12곳(현재 Production 공개) 그대로 유지
- 미래채움존 9곳을 *별도 구역*으로 추가하고, 번호를 `미래1~미래9`로 표시
- 최대 105곳. 탭은 `전체 · 초등 · 중등·특수 · 고등 · 미래채움 · 체험존` (모바일: `전체 · 초 · 중·특 · 고 · 미래 · 체험`)
- 운영자 화면도 2개 구역을 구분하고 긴 프로그램명을 전체 표시

## 검증으로 확인한 실제 Production (2026-11-04)
- 학교 공개 84 (초29/중25/특1/고29)
- 체험존 공개 12(게임4/교육8), 현재 `체험1~12`
- 미래채움존 `미래` 구역은 아직 없음
- 기존 public.booths_before_write와 private.rehearsal_live_reset는 체험존 포함
- **구 PR #66의 SQL을 그대로 실행 금지**: 함수 해시가 96곳 DB와 다르고, 그대로 재정의하면 체험 번호와 23시 초기화 범위를 훼손할 수 있음
- 구 PR #66의 공개 검사 기대값 93, 롤백 기대값 84는 이제 틀림. 새로운 기준은 공개 전 96 / 후 105 / 미래만 숨길 때 96

- `미래1` AI 로봇 플레이존, 기관 `에듀플라이플라이교육협동조합` -> 운영계획서 `AI로봇 플레이존 / 에듀플라이교육 협동조합`. 기관의 '플라이' 중복은 오타.
- `미래2` 채울샘 SW체험존 -> 운영계획서 `피지컬 컴퓨팅 체험존`

## 배포 및 DB 적용 전 필수
1. 원본 2026 최종 부스명부와 9곳의 번호·기관·부스명 확인(오타 수정). 체험존 12곳은 현행 이름 유지.
2. 미래채움 전용 **새** DB migration을 운영 중인 96곳 함수 기반으로 제작: 번호 규칙은 학교 + 체험 + 미래 각각 유지; 23시 초기화도 84+12+9 포함. 84와 12의 UUID/QR/PIN/상태/기록 변화 금지.
3. migration은 미래 9곳을 비공개로 INSERT, QR/PIN을 안전하게 발급/실물 1곳 검증, 그 뒤 공개
4. 격리된 DB에서 SQL/QR/PIN/23시 초기화 회귀 검사 후 실 DB read-only 사전 점검. 공개 후 105곳·탭 6개·운영자 구역 확인
5. 운영문서와 롤백: 미래 9곳만 숨기면 96으로 복구, 체험존은 그대로 유지. PR #65/#66은 병합하지 말 것.

**이 브랜치는 관람객/운영자 표시만 변경합니다. 현재 운영 DB 데이터 및 함수는 변경하지 않았습니다.**
