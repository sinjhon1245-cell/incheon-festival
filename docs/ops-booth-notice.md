# 운영자 알림 — 설계 · 적용 · 실기기 리허설

관리자(부스 운영 현황)가 확인 필요 · 미입력 · 구역 · 전체 공개 · 부스 1곳에 짧은 알림을 보내면, 운영자 화면(QR · PIN)이 열려 있고
보이는 동안 15~20초 안에 위쪽 띠로 뜨고, 운영자가 [확인했어요] 를 누르면 기록합니다. 웹 푸시는 쓰지 않습니다.

| 부분 | 어디 | 상태 |
|---|---|---|
| DB(표 3 · 함수 7) | `supabase/migration-booth-notice.sql` · `rollback-booth-notice.sql` (main) | **Production 미적용** |
| 관리자 화면 | `assets/booth-admin.js` · `.css` (main · GitHub Pages) | 함수가 없으면 ‘준비 중’, 서버 스위치가 꺼져 있으면 ‘꺼짐’ |
| 운영자 화면 | `booth-ctrl.html` · `assets/booth-ctrl.css` · `assets/config.js` · `live/build.sh` (booth-live · Vercel) | 설정 `boothNotices: false` — **묻지도 그리지도 않음** |

## 1. 지켜야 할 것과 어떻게 지키나

| 요구 | 구현 |
|---|---|
| 자기 부스 알림만 | 운영자 함수 `booth_ctrl_notice(p_token, …)` · `booth_session_notice(p_session, …)` 는 **부스 id 를 받지 않고** QR 열쇠 · PIN 세션에서 서버가 부스를 정함(기존 `booth_ctrl_*` · `private.booth_session_resolve` 와 같은 거절). 다른 부스 알림 id 는 ‘없음’ 과 똑같이 답함 |
| 상태 구분 | 대기(둘 다 없음) · 화면에 표시됨(`shown_at` — 띠를 그렸고 화면이 보일 때만) · 운영자 확인(`acked_at` — [확인했어요] 를 눌렀을 때만) · 만료(대기인 채로 3시간 또는 그날 자정). ‘전달 완료’ 는 없음 |
| 중복 발송 제한 | 같은 부스 · 같은 종류(stale · missing · zone · all · booth)는 10분 안에 다시 보내지 않음(`skipped:recent`). 관리자 보내기는 advisory 잠금으로 줄을 세워 두 관리자가 같은 순간에 보내도 겹치지 않음 |
| 대량 발송 실수 방지 | 칸을 열면 **아무 대상도 골라져 있지 않음**(예전처럼 ‘확인 필요’ · 정해진 문구가 미리 골라져 있지 않음). **부스 1곳**은 공개 부스 목록에서만 고름(글로 쓰지 않아 오타 · 여러 곳 섞임 없음). [미리보기] 에서 받을 부스번호 · 수 · 운영자 화면에 보일 문구를 그대로 고정 → [다음 — 마지막 확인] 에서 ‘받을 부스 N곳과 문구를 확인했습니다’ 체크 뒤에만 [보내기 (N곳)]. 구역 · 전체 공개는 수를 크게 · 굵은 띠로. 보내는 것은 미리보기에서 고정한 부스뿐이고 서버가 다시 셈 — 결과는 ‘화면에서 고른 N곳 → 보냄 M곳’ 과 서버가 뺀 부스(10분 안 같은 알림 · 그 사이 대상이 아님)를 나눠 보이고, 다르면 빨간 띠로 ‘화면에서 고른 부스와 서버가 확인한 부스가 다릅니다’. 보낸 뒤 쓰기 칸은 처음으로(같은 대상에 한 번 더 누르는 실수 방지) |
| 알림 확인 ≠ 상태 갱신 | 알림 함수는 `booth_live` · `booth_live_log` 를 읽지도 쓰지도 않음. 띠의 [확인했어요] 는 알림 기록만 — 상태가 그대로면 운영자가 아래 ‘맞아요’ 를 따로 누름 |
| 보일 때만 묻기 · 부하 | 화면이 보이는 동안만 서버가 정한 간격(켜짐 15~20초 · 꺼짐 5분)으로 묻고, 가려지면 쉼. 84곳이면 초당 약 4.7번 |
| 오류 시 | 연결 오류 → 20초 · 40초 · 80초 … 5분까지 늘려 다시. 연결이 돌아오면(`online` · 비행기 모드 해제) 기다리지 않고 0~3초 안에 다시. 함수 없음 · 실행 권한 없음 → 그 화면에서는 더 묻지 않음. 끝난 세션 · 바뀐 QR → 띠를 내리고 5분 쉼(대기 화면이 원래대로 알림) |
| 기존 입력 · 인증 유지 | 알림은 따로 묻고 따로 그림. 저장 흐름 · 로그인 · 탭 조율 코드는 그대로(바뀐 줄: 띠 칸 · 알림 묶음 · startPoll/stopAll/render 에 한 줄씩 · 클릭 한 줄) |
| 기본 비활성 | ① 운영자 화면 설정 `boothNotices: false`(Vercel 빌드도 원본에 `boothNotices: true,` 가 있을 때만 켬) ② 서버 스위치 `booth_notice_config.enabled = false`. **둘 다 켜야** 띠가 보임. ②는 행사 중 언제든 SQL 한 줄로 끌 수 있음 |

## 2. 적용 · 켜기 순서(각 단계 별도 승인)

1. **DB**(SQL Editor, **낮 10:00~17:00**. 22:30~23:30(23:00 자동 초기화)과 행사 운영 시간(11-06 · 07)은 피함): 적용 직전 읽기 전용으로 23:00 초기화 성공 · 부스 84곳 · 일괄 확인 함수 그대로인지 보고 `migration-booth-notice.sql` → 확인 표 11줄 모두 true(4번 ‘기본 꺼짐’ = false 확인). 서버 스위치는 꺼진 채.
2. **관리자 화면**: main 병합 → GitHub Pages. 스위치가 꺼져 있으면 [운영자 알림] 은 ‘꺼짐’.
3. **운영자 화면 코드**: booth-live 병합 → Vercel Production. 설정이 false 라 화면 · 요청 모두 지금과 같음.
4. **리허설용 켜기**(실기기 리허설 때만): booth-live `assets/config.js` 의 `boothNotices: true,` → 배포, 서버 스위치 켜기
   `update public.booth_notice_config set enabled = true, updated_at = now() where id = 1;`
5. 리허설이 끝나면 서버 스위치를 다시 끄고, 3장 기준으로 행사 사용 여부를 정합니다.

끄기(즉시): `update public.booth_notice_config set enabled = false, updated_at = now() where id = 1;` — 다음 묻기(최대 20초)부터 띠가 사라지고 보내기가 막힘.
되돌리기: `rollback-booth-notice.sql`(함수만 지움 · 기록 표 남음) — 운영자 화면은 ‘함수 없음’ 을 받고 더 묻지 않음, 관리자 화면 ‘준비 중’.

## 3. 실기기 리허설(11월 4일까지) — 통과하지 못하면 11월 6~7일에는 켜지 않습니다

**준비**
- 시험 부스: 실제 R부스 **2~3곳**(운영팀과 정함). 한 곳은 QR 로, 한 곳은 PIN(공통 PIN) 으로 연 휴대폰을 둡니다. 시험하지 않는 **다른 부스 기기 1대**도 함께 켜 둡니다(자기 부스 알림만 보이는지).
- 보내기는 **‘부스 1곳’** 으로 시험 부스에만. 리허설 중 구역 · 전체 공개 · 확인 필요 · 미입력으로는 보내지 않습니다(84곳 모두에 뜸).
- 부스 · QR · PIN 은 바꾸지 않습니다. 개별 PIN 재발급 · 리허설 채우기(84곳)도 하지 않습니다.
- 켜는 순서는 2장 4번(운영자 화면 설정 → 서버 스위치). 끝나면 서버 스위치부터 끕니다.

| # | 기기 · 상황 | 통과 기준 |
|---|---|---|
| 1 | 안드로이드 Chrome · QR 로 연 화면 | ‘부스 1곳’ 으로 보내고 20초 안에 띠, 관리자 상태 ‘화면에 표시됨’ |
| 2 | iPhone Safari · QR | 같음 |
| 3 | iPhone · PIN(공통 PIN) 로 연 화면 | 같음 · [확인했어요] → ‘운영자 확인’ |
| 4 | 시험하지 않는 다른 부스 기기 | 1~3 내내 띠가 뜨지 않음(자기 부스 알림만) |
| 5 | 관리자 화면 보내기 단계 | 칸을 열면 대상 없음 → 미리보기에 그 부스번호 1곳 · 문구 그대로 → 마지막 확인 체크 전에는 [보내기] 못 누름 → 결과 ‘화면에서 고른 1곳 → 보냄 1곳’ |
| 6 | 화면 끈 상태(잠금)에서 보냄 → 30초 뒤 켬 | 꺼져 있는 동안 ‘대기’, 켜고 20초 안에 띠 · ‘화면에 표시됨’ |
| 7 | 비행기 모드 1분 → 해제 | 오류 없이 다시 묻고 띠 표시(보통 몇 초, 늦어도 5분 안) |
| 8 | 띠가 있는 채로 대기시간 · 잠시 중단 · ‘맞아요’ 누름 | 기존과 같이 저장 · 관람객 화면 반영 |
| 9 | [확인했어요] 만 누름 | 대기 값 · 마지막 입력 시각 그대로(관리자 화면 · 점검 SQL **B** 지문) |
| 10 | 같은 부스에 ‘부스 1곳’ 을 10분 안에 다시 | 미리보기 0곳(10분 안 같은 알림) · 보내기 못 함 |
| 11 | 서버 스위치 끄기 | 20초 안에 띠 사라짐 · 관리자 [운영자 알림] ‘꺼짐’ |
| 12 | 운영자 10대 이상 동시에 켜 두고 30분 | 오류 없음 · Supabase API 요청 그래프에 이상 없음 |

판정: 1~11 모두 통과 + 12 에서 오류 없음 → 행사 때 켤지 따로 결정. 하나라도 실패하면 행사에는 켜지 않습니다(설정 false · 서버 스위치 끔 유지).

## 4. 행사 영향 · 위험

- 적용만 하고 켜지 않으면(1~3단계) 운영자 화면 · 관람객 화면 · 대기 입력에 영향 없음(요청 0건). 관리자 화면은 1분마다 켜짐 여부를 한 번 읽음.
- 켜면 운영자 화면마다 18초에 한 번 작은 요청 — 84곳이면 초당 약 4.7번. 실제 PostgreSQL 부하 시험(84곳 × 20번 동시)에서 오류 0.
- 위험(중간): 행사 직전 운영자 화면 배포 · 실기기마다 다른 동작(잠금 화면 · 절전). 그래서 기본 꺼짐 · 서버 스위치로 즉시 끄기 · 리허설 통과 조건을 둡니다.
- 웹 푸시(화면을 닫아도 알림)는 이번 범위가 아닙니다(서비스 워커 · 권한 · 발송 서버 필요, iPhone 은 홈 화면 추가 때만).
