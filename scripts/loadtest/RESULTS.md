모델 계산값입니다(측정값 아님). Supabase 처리 한도 가정 **400 RPS**, 부스 80곳, 관람객 1명이 600초마다 페이지를 새로 엶, 화면은 모두 켜져 있음(가장 나쁜 경우), 운영자 200명 + 관리자 20명이 함께 씀(7.7 RPS). 같은 인자로 돌리면 같은 표가 나옵니다.

### B 구조 (100,000명)

- 붕괴 여부: 관람객 몫 Supabase 요청이 최선 0.25 RPS, 최악 0.75 RPS → Supabase 는 관람객 수로 무너지지 않음. CDN→함수 호출은 최선 0.20 · 최악 310 RPS(함수 비용 · 동시 실행 한도 쪽 위험).
- CDN 의 origin 보호: cache hit 최선 100%, 최악 94.0%. 함수 memo 가 그 뒤를 한 번 더 막음.
- 오류 시 backoff · last-good · 자동 회복은 위 '장애 · 회복' 표와 같음. 남는 위험은 Vercel 쪽입니다: 초당 6,000건, 시간당 66.4GB 를 요금제가 받는가.
