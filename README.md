# 2026 인천 AI미래채움 교육페스티벌 — 행사 운영 포털

행사 관계자가 **준비 단계와 행사 당일 스마트폰으로 실제로 사용하는 운영 포털**입니다.
일반 관람객용 홍보 사이트가 아니라, 지금 무엇이 진행 중인지·어떤 부스에 문제가 있는지·
누구에게 연락해야 하는지를 빠르게 찾는 것이 목적입니다.

**포털에는 로그인 단계가 없습니다.** 주소를 아는 관계자는 바로 들어와 열람하고
현장 문제를 보고할 수 있습니다. 요청 **해결 완료**와 업무 **시작·완료**처럼
운영 상태를 바꾸는 일은 **로그인한 운영진만** 할 수 있습니다 — 관리자 화면에서
로그인하면 같은 브라우저의 포털에 처리 단추가 나타납니다.
운영 내용을 **편집하는 것은 관리자**이고, 관리자만 로그인합니다.

- 운영 포털: https://sinjhon1245-cell.github.io/incheon-festival/ (GitHub Pages · `main`)
- 관리자: https://sinjhon1245-cell.github.io/incheon-festival/admin.html (관리자 계정 로그인 필요)
- 부스 Live 사이트(관람객 · 부스 운영자): https://incheon-live.vercel.app/ (Vercel · `booth-live`)
- 배포 구조는 아래 ‘배포’ 를 보세요. Netlify 는 지금 쓰지 않습니다.

> 이 구조는 “링크를 아는 사람 = 관계자”로 보는 시연·운영용 설계입니다.
> 링크가 밖으로 전달되면 운영정보도 함께 보입니다. 검색엔진에는
> 올라가지 않지만(noindex), 주소 자체가 곧 열쇠라는 점을 감안해 주세요.

## 화면 구성

| 메뉴 | 내용 |
|---|---|
| 홈 | 행사명 · 슬로건 · 일시 · 장소, D-day·진행 상태, 운영 숫자 넉 장, 긴급 공지, 현재/다음 일정, 빠른 실행 |
| 일정 | 날짜 탭(이틀 행사), 시간순 타임라인, 오전·오후·분류 필터, 검색, 현재 일정 자동 강조 |
| 부스 현황 | 배치도, 구역·구분 필터, 검색, 상세 드로어(연관 요청·물품) |
| 공지 | 긴급/중요/일반, 고정 공지, 상세 보기 |
| 운영 요청 | 현장 문제 보고 등록, 처리 담당팀 표시, 해결 완료 처리 |
| 업무 배정 | **업무별 담당자 · 담당자별 업무** 두 보기, 업무마다 맡은 역할 표시, 업무 시작/완료 |
| 운영 물품 | 기관·팀·부스별 배부 현황(조회) |
| 자료실 | 운영 문서 링크 |
| 운영 인력 | 역할 필터·분류 필터·검색, 카드 맨 위 역할 표시. **전화번호는 표시하지 않습니다** |
| 행사장 | 장소 · 주소(지도 링크), 부스 배치도, 공식 운영구역, 주요 공간 |
| 운영 FAQ | 관계자용 아코디언 |

**일정 · 부스는 실제 데이터가 0건이면 “준비 중” 안내 아래에 협의용 예시가 기본으로 보입니다.**
담당자들이 화면을 보며 운영 흐름과 부스 구성을 협의할 수 있게 하려는 것입니다.

- 기본: “준비 중” 안내 → 그 아래 **협의용 예시 미리보기**(일정 4건 · 부스 4개,
  머리에 “협의용 예시 · 실제 행사 정보가 아닙니다”) → **[전체 협의용 예시 보기 →]**
- 전체 예시: 일정 16건(11. 6. 10건 · 11. 7. 6건) · 부스 10개가 실제 화면과 같은
  구조(날짜 · 오전/오후 · 분류 · 핵심 · 검색 / 구역 · 구분 · 검색)로 열립니다.
  맨 위 “협의용 예시” 띠와 **[예시 닫기]**, 카드마다 “예시” 표시가 붙습니다.
- 예시 부스의 A~E 는 협의용 임시 구역 코드입니다. 'A = 스쿨존' 처럼 정해진 것이
  아닙니다. 예시 일정에는 개막식 세부 순서 같은 분 단위 식순을 넣지 않습니다.
- 홈의 D-day · 운영 브리핑 · 숫자에는 예시가 절대 섞이지 않습니다.
- **실제 일정 · 부스가 한 건이라도 등록되면 미리보기 · 단추 · 예시가 모두 사라지고
  실제 데이터만 보입니다.** 코드 수정이 필요 없습니다. 예시는 화면
  (`assets/portal.js` 의 `SAMPLE_SCHED_ROWS` · `SAMPLE_BOOTHS`)에만 있고
  데이터베이스에 넣지 않습니다.

공지 · 운영 요청 · 업무 · 물품 · 자료실 ·
운영 인력 · FAQ 처럼 기능을 설명해야 하는 화면에는 카드마다 “예시” 표시가 붙은
예시가 보이며, 시각 · 부스 번호 · 장소처럼 실제 정보로 읽힐 값은 적지
않습니다. 실제 데이터가 한 건이라도 등록되면 예시는 사라집니다. 예시는 화면
(`assets/portal.js`)에만 있고 데이터베이스에는 넣지 않습니다.

모바일에서는 하단 고정 탭(홈·일정·부스·공지·더보기), PC에서는 좌측 사이드바를 씁니다.

| | 로그인 없는 관계자 | 관리자(운영진) |

| 운영 요청 등록 | ✔ | ✔ |

| 일정·공지·자료실·담당자·행사장·FAQ 편집 | — | ✔ |
| 운영 요청 상태 변경·삭제 | — | ✔ |
| 관리자 화면 접근 | — | ✔ |

화면에서 감추는 것이 아니라 **데이터베이스의 RLS 가 강제**합니다.
관리자 주소를 알아내도, API 를 직접 호출해도 권한이 없으면 바꿀 수 없습니다.

상태 변경은 표 전체에 쓰기 권한을 여는 대신, 상태 한 칸만 고치는
데이터베이스 함수로만 합니다. 네 함수 모두 **anon(로그인 없음) 실행 권한이
없고**, 함수 안에서 한 번 더 누구인지 확인합니다
(`migration-lock-portal-actions.sql`, 2026-10-01 적용).

| 함수 | 실행 | 함수 안 확인 |
|---|---|---|
| `resolve_operation_request(id)` | authenticated | `is_staff()` |
| `set_operation_task_status(id, status)` | authenticated | `is_staff()` |
| `set_booth_status(id, status)` | authenticated | `is_admin()` |
| `set_supply_target_status(id, status)` | authenticated | `is_admin()` |

`is_staff()` 는 `staff_profiles` 에 등록된 계정이면 참입니다(지금은 관리자
계정 aisw01~20 등이 모두 여기에 있습니다). 가입이 열려 있더라도, 명단에 없는
계정은 함수 안에서 거절됩니다.

포털 화면도 같은 규칙을 따릅니다. 로그인하지 않은 화면에는 “해결 완료 ·
업무 시작/완료” 단추가 나오지 않고, 목록 위에 “운영진 로그인 후 할 수
있습니다 · 로그인 →” 한 줄만 보입니다. 관리자 화면에서 로그인하면 같은
브라우저의 포털에서 단추가 보이고, 사이드바의 관리자 옆에 “로그인됨” 이 붙습니다.

## Supabase 설정

### 1. 연결 정보

`assets/config.js` 에 Supabase **Project URL** 과 **publishable(anon) 키**를 넣습니다.

```js
window.FESTIVAL_CONFIG = {
  supabaseUrl: 'https://xxxxx.supabase.co',
  supabaseAnonKey: 'sb_publishable_...'
};
```

> ⚠️ `service_role` 또는 secret 키는 **절대** 넣지 않습니다.
> publishable 키는 브라우저에 노출되도록 설계된 공개 키이고,
> 실제 권한은 데이터베이스의 RLS 정책이 막습니다.

이 파일은 저장소에 커밋되어 GitHub Pages 배포본(운영 포털)에도 함께 올라갑니다.
(부스 Live 사이트에는 `live/build.sh` 가 필요한 값만 옮긴 설정 파일이 올라갑니다.)
`.gitignore` 에 넣으면 배포본에서 “서버에 연결할 수 없습니다”가 뜹니다.

### 2. 스키마 실행

Supabase 대시보드 → **SQL Editor** 에서 순서대로 실행합니다.

1. `supabase/schema.sql` — 처음 설치할 때만
2. `supabase/migration-portal.sql` — 표와 칼럼 구조 (처음 설치할 때만)
3. `supabase/migration-public-portal.sql` — **현재 접근 정책. 반드시 실행**
4. `supabase/migration-media-support.sql` — **이미지 기능 · 운영 FAQ 15문항. 반드시 실행**
5. `supabase/migration-operations.sql` — **담당 업무 · 운영 물품. 반드시 실행**
6. `supabase/migration-fix-portal-actions.sql` — **포털의 해결 완료 · 업무 시작/완료. 반드시 실행**
7. `supabase/migration-schedule-event-date.sql` — **일정의 일자(이틀 행사). 반드시 실행**
8. `supabase/migration-event-dates-2026.sql` — 새 환경의 행사 기간 보정 (선택)
9. `supabase/migration-lock-portal-actions.sql` — **상태 변경을 운영진 전용으로. 반드시 실행**

10. `supabase/migration-booth-live.sql` — **부스 실시간 대기 현황 · 운영자 QR 열쇠.** 3번 뒤에 실행합니다

   수정까지 담은 전체 정의라, 다시 돌려도 그 기능이 되돌아가지 않습니다.

### 3. 관리자 계정

관리자 여부는 `staff_profiles.role = 'admin'` 으로 판단합니다.
관계자용 계정은 만들지 않습니다 — 포털에 로그인이 없기 때문입니다.

#### 로그인은 아이디로 합니다

Supabase Auth 는 이메일로만 로그인할 수 있지만, 관리자에게는
`aisw01` 같은 **아이디만** 알려 주면 됩니다. 로그인 화면이
`assets/config.js` 의 `adminIdDomain` 을 붙여 보냅니다.

```
aisw01  →  aisw01@aisw.local  →  signInWithPassword()
```

`@` 가 들어간 값을 치면 그대로 씁니다. 그래서 `aifest@ice.go.kr`
처럼 이메일로 만든 기존 계정도 예전과 똑같이 로그인됩니다.

#### 로그인 유지 · 비밀번호 변경 · 로그아웃

- **로그인 유지**: 한 번 로그인하면 그 브라우저(localStorage)에 남아, 새로고침하거나
  브라우저를 껐다 켜도 다시 로그인하지 않습니다(supabase-js `persistSession` ·
  `autoRefreshToken`). 따로 ‘로그인 유지’ 칸은 두지 않습니다. 공용 PC 에서는
  쓰고 나서 로그아웃하세요.
- **비밀번호 보기**: 비밀번호 칸 오른쪽의 눈 단추로 잠깐 보이게 할 수 있습니다.
- **내 비밀번호 변경**: 관리자 화면의 옆 메뉴(휴대폰은 ‘더보기’) → 내 비밀번호 변경.
  현재 비밀번호를 확인한 뒤 바꾸고, 바꾸면 **다른 기기의 로그인은 끝납니다**(이 기기는
  그대로). 8자 이상. 관리자 계정 주소(aisw01@…)는 메일을 받을 수 없어 ‘비밀번호
  찾기’ 메일은 없습니다 — 잊어버리면 총괄 관리자가 Supabase → Authentication →
  Users 에서 다시 정합니다.
- **로그아웃**: 이 기기의 로그인만 끝납니다. 다른 기기까지 끝내려면 비밀번호를 바꿉니다.

#### 한 개만 만들 때

1. Supabase → **Authentication → Users → Add user**
   (이메일·비밀번호 입력, *Auto Confirm User* 켜기)
2. `migration-portal.sql` 이 `aifest@ice.go.kr` 을 자동으로 관리자로 등록합니다.
   다른 주소를 쓰면 그 파일 마지막의 이메일을 바꾸세요.

#### 여러 개를 한 번에 만들 때 (aisw01 ~ aisw20)

`scripts/create-admin-users.mjs` 가 Auth 계정 생성과
`staff_profiles` 연결(`role='admin'`)을 한 번에 합니다.

```powershell
.\scripts\create-admin-users.ps1            # 확인만 — 아무것도 만들지 않습니다
.\scripts\create-admin-users.ps1 -DryRun    # 만들 목록까지 보여 줍니다
.\scripts\create-admin-users.ps1 -Apply     # 실제로 만듭니다
```

- **service_role 키**를 물어봅니다. Supabase → Project Settings → API 에 있습니다.
  키는 그 창의 환경변수로만 쓰이고 파일에 남지 않습니다.
  ⚠️ 이 키는 RLS 를 전부 무시합니다. `assets/config.js` 나 git 에 절대 넣지 마세요.
- 이미 있는 계정은 **건너뜁니다.** 덮어쓰거나 비밀번호를 바꾸지 않습니다.
- `aifest@ice.go.kr` 은 보호 목록에 있어
  대상에 섞이면 스크립트가 멈춥니다. 생성 전후를 대조해 변화가 없는지도 확인합니다.
- 초기 비밀번호는 16자 무작위(대·소문자·숫자·특수문자 포함)로 계정마다 다릅니다.
  `admin-accounts.csv` 로 저장되며 `.gitignore` 에 걸려 있습니다.
  **전달이 끝나면 지우세요.**

#### 비밀번호만 다시 나눠 줄 때

계정은 그대로 두고 비밀번호만 바꿉니다. **전용 스크립트가 따로 있습니다.**

```powershell
.\scripts\reset-admin-passwords.ps1            # 확인만
.\scripts\reset-admin-passwords.ps1 -DryRun    # 새 비밀번호까지 만들어 검사(전송 안 함)
.\scripts\reset-admin-passwords.ps1 -Apply     # 실제 변경
```

`reset-admin-passwords.mjs` 에는 계정을 만들거나 지우는 코드가
**없습니다.** 쓰는 것은 `PUT /auth/v1/admin/users/<uid>` 하나뿐이고
본문에 `password` 말고는 싣지 않습니다. 그래서 UID ·
`staff_profiles` · `role` 이 움직일 수 없습니다. 계정을 만드는 일은
`create-admin-users.mjs` 가 따로 맡습니다 — 비밀번호를 바꾸려다
계정이 새로 생기는 사고를 코드 수준에서 막으려고 나눠 두었습니다.

- 재설정 비밀번호는 **8자** 입니다(나눠 주기 쉽도록).
  ⚠️ 8자는 약 49비트로, 16자(98비트)보다 훨씬 약합니다. 관리자 계정은
  운영 콘텐츠 전체를 편집할 수 있으므로, **행사가 끝나면 계정을 정리**하거나
  `ADMIN_PW_LENGTH` 로 길이를 올리는 것을 권합니다.
- 바꾸고 나면 예전 비밀번호는 즉시 못 씁니다. 이미 나눠 준 것이 있다면 다시 전달해야 합니다.
- 없는 계정이 있으면 만들지 않고 멈춥니다. 먼저 `create-admin-users.ps1 -Apply` 를 돌리세요.
- 새 비밀번호는 `admin-accounts.csv` 에 **덮어써집니다**(`.gitignore` 제외).

두 스크립트는 `scripts/lib/admin-api.mjs` 를 같이 씁니다. 비밀번호
규칙과 계정 대조 방법이 한 곳에만 있어야, 한쪽만 고쳐지고 다른 쪽이
조용히 어긋나는 일이 없습니다.

아이디를 바꾸거나 도메인을 바꾸려면 `scripts/lib/admin-api.mjs` 의
`IDS` · `ID_DOMAIN` 과 `assets/config.js` 의 `adminIdDomain` 을
**같이** 고쳐야 합니다. 두 값이 어긋나면 로그인되지 않습니다.

## 이미지 (안내도 · 배치도 · 공간 사진)

이미지는 Supabase Storage 의 `festival-images` 보관함에 들어갑니다.
보관함은 공개라 포털에서 로그인 없이 보이고, 올리고 지우는 것은
관리자만 할 수 있습니다(보관함 정책이 `is_admin()` 으로 막습니다).

| 이미지 | 관리자에서 올리는 곳 | 포털에서 보이는 곳 |
|---|---|---|
| 행사장 전체 안내도 | 행사 기본정보 | 행사장 맨 위 |
| 주요 공간 사진 | 행사장 관리 → 각 공간 | 행사장의 공간 카드 |
| 전체 부스 배치도 | 행사 기본정보 | 부스 현황 맨 위 |
| 부스 대표 이미지 | 부스 관리 → 각 부스 | 부스 상세 |

올리는 방법은 어디서나 같습니다. **이미지 선택 → 미리보기 확인 →
저장.** 주소를 복사해 붙여넣을 일은 없습니다. 이미 있는 이미지를
바꾸면 예전 파일은 저장이 끝난 뒤 보관함에서 자동으로 지워집니다.

- 형식: JPG · PNG · WebP
- 크기: 10MB 이하 (브라우저와 보관함 양쪽에서 막습니다)
- 안내도는 가로형(16:9 정도)을 권합니다
- 이미지를 비우면 화면은 “준비 중” 안내로 자연스럽게 돌아갑니다

이미지 설명(alt)은 화면을 읽어 주는 도구가 대신 읽는 문장이고,
캡션은 이미지 아래에 그대로 보이는 한 줄입니다. 둘 다 선택입니다.

### 관리자 목록 · 입력창

일정 · 부스는 수십 건 단위로 입력하는 것을 전제로 만들었습니다.

- **일정**: 날짜(11. 6.(금) · 11. 7.(토))별 묶음, 시각순 정렬. 날짜 칩 ·
  구분 · 상태 걸러 보기, 일정명 · 장소 · 담당팀 · 담당자 검색. 입력창은
  무엇을 → 언제 → 어디서 · 누가 → 운영 상태 순서이고, 날짜는 행사 기간 단추로만,
  시각은 [오후 2시][30분] 고르기 상자(10분 단위)로 고릅니다. 시작을 고르면
  종료가 30분 뒤로 제안되고, +30분 · +50분 · +1시간 · +1시간 30분 · +2시간
  단추가 있습니다. 10분 단위가 아닌 예전 값(예: 14:05)은 그대로 남습니다.
- **부스**: 구역별 묶음(미배정은 맨 아래), 부스 번호 자연순(A-2 < A-10) 정렬.
  맨 위 **요약 카드**(전체 · 공개 · 비공개 · 미배정 · QR 미발급 · 확인 필요)를 누르면 그 부스만 거르고,
  다시 누르거나 ‘전체’ 를 누르면 풉니다(고른 카드는 보라색). 그 아래는 숫자를 되풀이하지 않습니다 —
  구역 칩(구역이 여섯 이하면 ‘A 4’ 처럼 짧게, 더 많으면 고르기 상자) · 기관 유형 · 상태 · 운영 필요
  (전기/네트워크) 고르기 상자, 번호 · 부스명 · 기관 · 담당자 · 프로그램 검색, 조건이 있을 때만
  **[필터 초기화]**. 결과 줄은 ‘전체 12건 중 3건’. 휴대폰에서는 [부스 검색][필터 n] 한 줄로 접고,
  ‘필터’ 를 누르면 아래에서 패널이 올라옵니다([초기화] · [결과 보기]). 위치는 구역 [A▼] 과
  번호 [12] 두 칸으로 고르고, 표시 번호(A-12)는 데이터베이스가 만듭니다(손으로
  적는 칸 없음). 같은 구역의 같은 번호는 저장되지 않습니다. 구역 · 번호가 정해지기
  전에도 **미배정**으로 먼저 등록할 수 있습니다. 목록 · 수정창의 **공개 ON/OFF** 를
  켜야 관람객 · 포털 · 운영자 화면에 나옵니다 — 구역과 번호가 있고 구역도 공개여야
  켜집니다. 구역 · 번호를 비우면 저절로 비공개가 되고, 다시 정해도 공개는 직접 켭니다.
  구역(코드 · 이름 · 설명 · 표시 순서 · 공개)을 비공개로 바꾸면 그 구역 부스는 모두
  가려지지만 부스의 공개 값은 그대로입니다. 구역을 지우면 부스는 지워지지 않고
  미배정 · 비공개가 됩니다(운영자 QR · 대기 기록은 남음). 담당자 · 연락처 · 운영
  메모 · 특이사항은 수정창의 ‘관리자 전용 정보’(`booth_private` 표)에 적습니다.
  > 이 동작은 `supabase/migration-booth-master-data.sql` · `migration-booth-private.sql`
  > 적용이 전제입니다(아직 운영 DB 에 적용하지 않은 초안).
- 모든 입력창: 제목 · 단추 줄은 고정, 본문만 스크롤. 오류는 저장 단추 위와
  해당 칸 아래에 함께 나오고 그 칸으로 초점이 옮겨 갑니다.

|---|---|---|
| 운영 인력 → 역할 구분 | `contacts.role_group` | 그 사람의 기본 운영 역할군 (부스지원·전산지원 …) |
| 운영 인력 → 담당업무 | `contacts.duty` | 그 사람이 맡은 일에 대한 설명 |
| 업무 배정 → 업무 배정 역할 | `task_assignments.role` | **그 업무에서만** 맡은 몫 (총괄·현장 확인·기록 …) |
| 업무 배정 → 업무 분야 | `operation_tasks.area` | 업무를 묶는 분야 (기념식·부스 운영·안전) |

역할 구분의 추천값은 **총괄 · 운영본부 · 부스지원 · 전산지원 · 운영지원 ·
안전지원 · 안내 · 기타** 입니다. 데이터베이스가 값을 제한하지는 않아서,
추천 목록에 없는 예전 값도 그대로 쓰이고 수정 창에 “(이전 값)” 으로
남습니다. 포털의 역할 필터는 **실제로 등록된 역할만** 보여 줍니다.

담당자(연락망)에서 **‘운영 인력’ 을 켜고 역할 구분을 고른 사람**만 포털
카드 맨 위에 역할이 붙고 역할 필터에 잡힙니다. 그 밖의 연락처(시설·협력기관
등)는 지금까지의 카드 모양 그대로입니다.

### 개인 연락처

**공개 포털에는 전화번호를 두지 않습니다.** 담당자·부스 상세·담당 업무
어디에도 번호와 전화 단추를 표시하지 않습니다. 포털은 로그인이 없어서
주소를 아는 사람이면 누구나 열 수 있고, 거기에 개인 휴대전화가 적혀
있으면 링크 하나로 명부가 통째로 나갑니다.

화면에서 지운 것만으로는 부족해서 표도 나눴습니다. 개인 휴대전화 · 관리자
메모는 `contact_private` 표(관리자만 읽고 쓰기, RLS `is_admin()`)에 따로
둡니다 — 관리자 → 운영 인력 수정창의 “관리자 전용 정보”. `contacts.phone` 과
`booths.manager_phone` 칸은 예전 값을 비우기 위해서만 남아 있고(새로 적는
칸은 없음, 예전 값이 있는 줄에만 수정창에 보입니다), 포털은 이 칸을 아예
요청하지 않습니다. 이 두 칸은 로그인 없이 읽히는 표에 있으므로 **값을 넣지
마세요.** 공용번호(운영본부 · 기관 대표번호)는 기본정보의 “운영 문의 전화” 에
적습니다. 부스의 담당자 · 연락처 · 운영 메모 · 특이사항은
`migration-booth-private.sql` 적용 뒤 `booth_private` 표(관리자 전용)로 옮겨지고
`booths` 에서는 그 칸이 사라집니다.

## 실제 행사 정보 입력 위치

행사 기본정보(이름·기간·장소·주소)는 확정값이 들어 있습니다.
**운영 콘텐츠는 아직 비어 있고, 화면에는 “준비 중” 안내나 예시가 보입니다.** 아래를
관리자에서 채우면 실제 내용으로 바뀝니다.

- **운영 일정** — 시작·종료 시각은 `HH:MM`, **일자는 11/6 또는 11/7**.
  이틀 행사라 일자를 골라야 그 날짜 탭에 들어갑니다.
- **부스 구역 → 부스 목록** — 부스는 구역에 속하므로 구역부터 등록합니다.
- **운영 인력** · **자료실 링크** · **행사장 주요 공간**
- **업무 배정** · **운영 물품 배부 대상**
- **운영 FAQ 답변** — 15문항이 답변 빈칸·비공개로 들어 있습니다.
  답변을 채우고 공개를 켜야 포털에 나옵니다.
- **배치도 이미지** — 행사 기본정보에서 올립니다.
  비어 있으면 포털에 “배치도 준비 중”으로 표시됩니다.
- **운영 문의 전화 · 메일** — 행사 기본정보에서 넣습니다. 예전 자리표시값
  (`032-000-0000` · 관리자 계정 주소였던 `aifest@ice.go.kr`)은 비웠습니다.
  값을 넣으면 포털 행사장 화면의 장소 카드에 “운영 문의” 한 줄로 보이고,
  비어 있으면 그 줄이 나오지 않습니다. 관리자 로그인 아이디와는 별개입니다.

확인되지 않은 값을 사실처럼 채우지 마세요. 비워 두면 화면에
“미정 / 준비 중”으로 표시되도록 만들어 두었습니다.

## 부스 실시간 대기 현황

관람객은 “지금 어느 부스가 한가한지” 를 휴대폰으로 보고, 부스 담당 선생님은
줄이 바뀔 때마다 대기 시간을 한 번 누릅니다. 동료가 만든 이식 패키지에서
출발했지만, 모든 부스가 같은 PIN 을 쓰던 방식을 버리고 **부스마다 다른 QR
열쇠**로 다시 만들었습니다.

**사이트는 둘입니다.** 같은 저장소를 사이트 두 개로 배포합니다. 운영 포털은
GitHub Pages(`main`), 부스 Live 사이트는 Vercel 프로젝트 `incheon-live`(`booth-live`)입니다
(아래 ‘배포’ 참고. `live/` 의 Netlify 설정은 예비입니다).

| 사이트 | 올라가는 화면 | 누가 여나 |
|---|---|---|
| **운영 포털** (GitHub Pages) | 포털 `index.html` · 관리자 `admin.html` · 부스 운영 현황 `booth-admin.html` · QR 인쇄 `print-qr.html` | 관계자 · 운영본부 |
| **부스 Live 사이트** (Vercel 프로젝트 `incheon-live`, `live/`) | 관람객 화면(사이트 첫 화면, 원본은 `visitor.html`) · 부스 운영자 화면 `booth-ctrl.html` | 관람객 · 부스 담당 선생님 |

종이에 찍히는 QR 은 관람객용이든 운영자 카드든 **모두 부스 Live 사이트**를
가리킵니다. 관람객도 부스 선생님도 운영 포털 주소를 받지 않습니다. QR 인쇄만
운영 포털에 남는 것은 열쇠를 받으려면 관리자 로그인이 있어야 하고, 그 로그인이
관리자 화면(`admin.html`)과 같은 사이트에 저장되기 때문입니다.
(운영 포털에도 `visitor.html` · `booth-ctrl.html` 이 같은 원본으로 함께 올라갑니다.
`?demo` 미리 보기용이고, 종이 QR 은 그쪽을 가리키지 않습니다.)

| 화면 | 누가 | 어디서 | 하는 일 |
|---|---|---|---|
| 관람객 화면 (`visitor.html`) | 관람객 | **부스 Live 사이트의 첫 화면**. 입구 포스터 · 부스 앞 안내 QR | 부스별 대기 시간과 여유 · 보통 · 혼잡, 구역 탭 · 검색, ‘한눈에’ 칸 보기. 행사 시간에 주기적으로 다시 읽음(공식 주소 https://incheon-live.vercel.app/ — 운영 포털(GitHub Pages)의 `visitor.html` 은 이 주소로 보내는 진입 페이지이고 `?demo=1` · `?b=` 만 옮김). 부스 번호는 늘 전체(`A-07`)로 보이고, 구역 탭은 짧은 이름(‘A 스쿨존 20’), 구역이 7개 넘으면 [전체] + [구역 선택], 부스가 20곳 넘으면 위에 검색칸이 나옴. 검색 순서는 부스 번호 → 이름 → 체험 내용 → 운영기관 → 구역 이름. 부스 앞 QR(`?b=부스`)로 열면 그 부스와 같은 구역의 여유 부스를 맨 위에 보여 줌 |
| 부스 운영자 화면 (`booth-ctrl.html`) | 부스 담당 선생님 | **부스 Live 사이트**. 부스별 **운영자 카드의 QR**(`#k=열쇠`)로만 열림 | 바로 · 5 · 10 · 15 · 20 · 30 · 45 · 60분 이상 중 하나를 누름. 잠시 중단 · 오늘 마감. 처음 열 때 “이 부스를 운영하시나요?” 확인 |
| QR 인쇄 (`print-qr.html`) | 운영본부 (관리자 로그인) | **운영 포털(GitHub Pages) 주소**. 관리자 → 부스 화면 위 ‘부스 QR 인쇄’ | ① 부스 운영자용 카드(A4 한 장에 4개) ② 부스 앞 안내(A4 한 장에 2개) ③ 입구 포스터. ① 카드마다 화면에만 보이는 관리 단추: QR 크게 보기 · 열쇠 끄기 · 대기 값 직접 고치기 · 열쇠 바꾸기. 실시간 값 모두 지우기. 화면을 연다고 열쇠가 생기지 않습니다 — ‘QR 미발급’ 카드의 [운영자 QR 발급] 이나 [배정 완료 부스 QR 일괄 발급] 으로 만듭니다(구역 · 번호가 있는 부스만, 공개 전에도 가능 · 공개 전에는 QR 이 동작하지 않음). 부스가 많을 때: 구역 단추로 그 구역만 고르기 · **[구역별로 새 페이지에서 시작]**(구역이 바뀌면 새 장부터) · **[인쇄 화면으로 보기]**(관리 단추 · 경고를 숨기고 종이에 찍힐 카드만). 카드 크기(운영자 카드 QR 42mm · 부스 앞 안내 QR 78mm)는 그대로입니다 |
| 포털 **부스 현황** | 관계자 | 운영 포털 | 부스 카드 · 상세에 지금 대기 상태. 맨 위 ‘부스 대기 입력’ 줄(입력 중 · 30분 넘게 그대로 · 아직 없음)을 펼치면 입력이 오래된 부스부터 보임. 부스 화면을 보는 동안 1분마다 다시 읽음 |

혼잡도는 선생님이 고르지 않습니다. 대기 시간만 누르면 데이터베이스 함수가
정합니다 — **10분 이하 여유 · 25분 이하 보통 · 그 위 혼잡**. 부스마다
‘혼잡’ 의 기준이 다르면 관람객 화면의 색이 뜻을 잃기 때문입니다.
운영본부가 ‘대기 값 직접 고치기’ 로 넣는 값도 같은 규칙을 따릅니다.

### 왜 이렇게 만들었나

- **운영자 열쇠는 아무도 직접 읽을 수 없는 표에 있습니다.** `booth_access` 는
  anon · 로그인 사용자 모두 권한이 없고, 입력 함수(`booth_ctrl_get` ·
  `booth_ctrl_set` · `booth_ctrl_touch`)가 열쇠를 받아 맞는 부스 한 곳만
  바꿉니다. 열쇠는 부스마다 무작위 24자라 짐작할 수 없고, 한 부스의 열쇠가
  새도 다른 부스는 안전합니다.
- 열쇠는 주소의 `#` 뒤에 있어 서버 기록이나 Referer 로 새지 않고, 입력 함수는
  POST 로만 불립니다.
- 관람객이 읽는 `booth_live` 표에는 부스 id · 상태 · 대기 시간 · 시각만
  있습니다. `booths` 표는 건드리지 않습니다. 누른 기록은 `booth_live_log` 에
  남고(언제 · 무엇을), SQL Editor 에서만 읽힙니다.
- **부스 Live 사이트를 따로 둔 것은 관람객과 부스 선생님이 운영 포털 주소를
  알게 되지 않게 하려는 것입니다.** `live/build.sh` 가 두 화면과 그 화면들이
  쓰는 파일, 그리고 필요한 값만 담은 설정 파일로 배포본을 만듭니다. 관리자
  로그인 도메인은 넣지 않고, 배포본에 QR 인쇄 · 관리자 화면 이름이나 운영 포털
  주소가 하나라도 섞여 있으면 빌드를 멈춥니다. 두 화면이 부르는 파일이 배포본에
  빠져 있어도 멈춥니다.
- **열쇠 끄기 · 관리자 직접 수정**(`migration-booth-live-admin.sql`). 꺼진 열쇠는
  운영자 화면이 모르는 열쇠와 똑같이 거절합니다. 다시 켜는 길은 ‘열쇠 바꾸기’
  하나뿐이고, 그때는 새 열쇠가 나옵니다(꺼 둔 예전 열쇠는 되살아나지 않습니다).
  운영본부가 열쇠 없이 고친 값은 입력 기록에 `source = 'admin'` 으로 따로 남습니다.
- **Realtime 은 쓰지 않습니다.** 입력 한 번이 보고 있는 사람 수만큼 메시지가
  되어 Supabase 요금제 한도(동시 연결 · 초당 메시지)에 금방 닿고, 넘으면
  프로젝트 전체의 실시간 연결이 끊깁니다. 대신 관람객 화면 주기적 다시 읽기 · 운영자 화면
  60초 · 포털 1분마다 다시 읽습니다. 숫자가 몇 초 늦는 대신 사람이 몰려도
  멈추지 않습니다.
- 다른 날 입력한 값과 그날 문 여는 시각(기본정보의 시작 시각) 전에 입력한
  값은 관람객 화면에 쓰지 않습니다. 리허설 값이나 첫날 ‘마감’ 이 둘째 날
  아침에 보이지 않게 하려는 것입니다. 30분 넘게 바뀌지 않은 값은 흐리게
  보여 주고 ‘확인 필요’ 를 붙입니다(‘마감’ 은 그날 안에는 흐려지지 않습니다).
  관람객 화면에는 마지막 입력 시각(‘방금’ · ‘N분 전’ · ‘HH:MM에 입력’)을 쓰지 않고
  지금 상태만 보여 줍니다 — 입력 시각은 부스 운영 현황(관리자)과 운영자 화면에서 봅니다.

### 켜는 순서

1. **DB** — Supabase 대시보드 → SQL Editor 에 `supabase/migration-booth-live.sql` 을
   통째로 붙여 넣고 Run 합니다. 표 셋(`booth_live` · `booth_access` · `booth_live_log`)과
   함수 여덟(운영자용 셋 · 관리자용 다섯 — 열쇠 끄기 · 직접 수정 포함)이 만들어지고,
   맨 아래 확인 표의 1~22번 ‘맞음’ 이 모두 true 여야 합니다.
   운영 DB 에는 2026-10-02 에 처음 판 → `migration-booth-live-admin.sql`(차이분) 순서로
   이미 적용돼 있습니다. 두 길은 같은 결과입니다.

   `booths` 표는 바뀌지 않고, 기존 대기 값 · 열쇠 · 기록도 지우지 않습니다.
   실행 전에도 화면들은 깨지지 않습니다(관람객 화면은 “부스별 대기 시간은 행사
   당일부터 표시돼요”, 운영자 화면은 “부스 대기 현황 기능이 아직 켜지지 않았어요”).

   > **고치려고 다시 실행할 때는 `migration-booth-live.sql` 하나만 실행합니다**
   > (예: 누가 보안 점검 경고를 보고 anon 실행 권한을 거뒀을 때). 전체 정의라
   > 열쇠 끄기 · 직접 수정도 그대로 남고, 꺼 둔 열쇠는 끌 때 문자열까지 바꿔
   > 두었기 때문에 되살아나지 않습니다. 여러 번 실행해도 안전합니다.

   > Supabase 보안 점검(Advisors)이 `booth_ctrl_*` 세 함수에
   > `anon_security_definer_function_executable` 경고를 띄웁니다. **의도된
   > 것입니다.** 부스 선생님은 로그인하지 않고 QR 열쇠로만 들어오므로 anon 이
   > 실행할 수 있어야 하고, 함수 안에서 열쇠를 확인합니다. 경고를 보고 실행
   > 권한을 거두면 모든 운영자 화면이 멈춥니다. `admin_*` 함수에 뜨는
   > `authenticated_security_definer_function_executable` 경고도 같습니다 —
   > 함수 안의 `is_admin()` 이 막고, 권한을 거두면 인쇄 화면이 멈춥니다.

2. **부스 Live 사이트** — 지금은 **Vercel 프로젝트 `incheon-live`** 입니다
   (Production Branch `booth-live` → `https://incheon-live.vercel.app/`).
   새로 만들 때는 *Add New… → Project* 에서 이 저장소를 Import 합니다. 빌드 명령 · 배포 폴더 · 헤더 · 빌드를 건너뛸 조건은
   `live/vercel.json` 이 정하므로, 대시보드에서는 아래만 맞춥니다.

   | Vercel 설정 | 값 |
   |---|---|
   | Framework Preset | `Other` |
   | Root Directory | `live` |
   | ↳ Include files outside the root directory in the Build Step | **켬** — 두 화면 원본이 `live/` 밖에 있습니다. 꺼져 있으면 `빌드 중단: ../assets/config.js 가 없습니다` 로 멈춥니다 |
   | ↳ Skip deployments when there are no changes to the root directory … | **끔** — 켜 두면 `visitor.html` 만 고친 push 가 배포되지 않을 수 있습니다 |
   | Build / Output / Install Command | 그대로(Override 끔). `vercel.json` 이 `sh build.sh` · `dist` · 설치 없음으로 정합니다 |
   | Settings → Environments → Production → Branch | `booth-live` (지금 설정. `main` push 는 미리 보기로만 배포됩니다) |
   | Environment Variables | 없음 |

   Import 직후 첫 배포는 기본 브랜치(`main`)로 돕니다. 그 브랜치에 `live/` 가 없으면
   `Error` 로 끝나는 것이 정상입니다. Production Branch 를 바꾼 뒤 그 브랜치에
   push 하거나 Deployments 에서 그 브랜치로 새로 배포합니다. 주소는
   `https://프로젝트이름.vercel.app/` 입니다(**QR 인쇄 뒤에는 바꿀 수
   없으니** 프로젝트 이름을 행사 내내 쓸 이름으로 정합니다). Production 이 아닌
   브랜치의 미리 보기 배포는 Vercel 로그인이 있어야 열리므로(Deployment
   Protection) 관람객 주소로 쓰지 않습니다.

   **(예비 · 현재 미사용) Netlify 로 옮길 때** — Netlify 에서 *Add new site → Import an existing project*
   로 이 저장소를 한 번 더 고르고, **Branch 는 `main`, Base directory 는 `live`**
   로 지정합니다. 빌드 명령(`sh build.sh`) · 배포 폴더(`dist`) · 헤더 · 빌드를
   건너뛸 조건은 `live/netlify.toml` 이 정합니다. 두 화면과 관계없는 파일만 바뀐
   push 에는 다시 배포하지 않습니다(앞 배포와 비교할 수 있을 때만 건너뛰고,
   캐시 없이 도는 빌드는 언제나 빌드합니다).
   사이트 이름(`https://이름.netlify.app/`)은 이때 정합니다. **QR 을 인쇄한 뒤에는
   바꿀 수 없으니** 행사 내내 쓸 이름으로 정합니다.
   **첫 배포가 Deploys 에서 `Published` 로 끝났는지 확인합니다.** `Canceled` 로
   나오면 Deploys → Trigger deploy → **Clear cache and deploy site** 를 누릅니다
   (화면에 따라 site 대신 project 라고 적혀 있습니다) — 캐시 없는 빌드는 건너뛰지
   않으므로 반드시 빌드됩니다. 그래도 안 되면 Site(Project) configuration →
   Build & deploy → **Build hooks** 에서 훅을 하나 만들어 그 주소로 POST 합니다
   (Netlify 는 빌드 훅으로 부른 빌드에는 건너뛰기 조건을 적용하지 않습니다).
   그냥 ‘Deploy site’ 는 건너뛰기 조건을 그대로 따르니 해결책이 아닙니다.
   `Failed` 이고 로그에 `빌드 중단: …` 이 있으면 아래 ‘문제가 생겼을 때’ 를 보세요.

   **확인:** 휴대폰으로 그 https 주소의 첫 화면(관람객 화면)과
   `…/booth-ctrl.html?demo`(협의용 예시 운영자 화면)가 열리는지 봅니다.
   내 컴퓨터에서 미리 보려면 Git Bash 에서 `sh live/build.sh` →
   `live/dist/` (`.gitignore` 에 걸려 있으니 확인한 뒤 지워도 됩니다).
3. **설정** — 2의 https 주소가 휴대폰에서 실제로 열리는 것을 확인한 **뒤에만**
   `assets/config.js` 의 **`visitorSiteUrl` 과 `staffSiteUrl` 둘 다에** 그 주소를
   넣고 push 합니다. 두 값이 같은 것이 맞습니다 — 관람객 화면과 운영자 화면이 한
   사이트에 있기 때문입니다. **그 전에는 둘 다 비워 둡니다.** 주소를 짐작해 넣지
   마세요. 없는 주소가 찍힌 QR 은 인쇄해 붙인 뒤에는 되돌릴 수 없습니다.

   | 값 | 넣을 것 | 비어 있거나 틀리면 |
   |---|---|---|
   | `visitorSiteUrl` | 부스 Live 사이트 첫 화면 주소 (`https://…/`) | 인쇄 화면이 ② ③ 관람객용 QR 을 만들지 않습니다. 운영 포털 주소(Netlify · 그 미리 보기 배포 · GitHub Pages · 인쇄하는 페이지 자신), http 주소, 내 컴퓨터 주소도 막습니다 |
   | `staffSiteUrl` | **같은** 부스 Live 사이트 주소. 운영자 카드 QR 은 `이 주소 + booth-ctrl.html#k=열쇠` | 인쇄 화면이 ① 운영자 카드를 만들지 않습니다(http · 내 컴퓨터 주소도 막음) |
   | `boothHelpLine` | 예: `운영본부: 1층 본부석` (한 줄 · 작은따옴표 · 글 안에 `'` 와 `\` 없이) | “운영본부에 문의해 주세요” |

   부스 Live 사이트에는 이 파일이 그대로 올라가지 않습니다. `live/build.sh` 가
   연결 값 넷과 `boothHelpLine` 만 옮기고, `visitorSiteUrl` 은 같은 사이트의 첫 화면(`./`)으로
   둡니다(관람객이 운영자 카드를 찍었을 때 보내는 곳). 운영자 화면에는 다른 화면으로 가는 링크가 없습니다.

4. **부스 등록** — 관리자 → 부스 구역 → 부스. 인쇄 전에 끝냅니다
   (아래 ‘주의’ 의 첫째 줄).
5. **인쇄** — **운영 포털 주소(https://sinjhon1245-cell.github.io/incheon-festival/)에서 관리자로 로그인한 채로**
   `print-qr.html` 을 엽니다(관리자 → 부스 화면 위 ‘QR · PIN 관리’ — 주소는 예전 그대로). ① 운영자
   카드를 열 때 부스마다 열쇠가 처음 만들어집니다. 모든 QR 아래에 가리키는
   주소가 작게 찍힙니다. 부스 Live 사이트 주소인지 보고, 한 장 먼저 뽑아
   휴대폰으로 찍어 본 뒤 나머지를 인쇄하세요.
   **인쇄한 뒤에는 부스 Live 사이트의 이름(주소)을 바꾸지 마세요.** 종이에
   찍힌 QR 이 모두 죽습니다.
6. **리허설 → 지우기** — 실제 카드로 휴대폰 몇 대에서 눌러 봅니다.
   **행사 전에는 관람객 화면에 숫자가 뜨지 않는 것이 정상입니다.** 관람객 화면은
   운영 시간(기본정보의 시작 시각부터)에만 대기 값을 쓰므로, 그 전에는 ‘D-N’ 이나
   ‘오늘 10:00에 문을 열어요’ 만 보입니다. 고장이 아니니 기본정보의 시작 시각을
   옮겨 맞추지 마세요 — 포털의 D-day 와 일정 화면까지 함께 바뀝니다.
   누른 값이 제대로 저장되는지는 이렇게 확인합니다.
   - 운영자 화면 맨 위 상태 판에 방금 누른 값이 뜨는지. 행사 전에는 이 판의
     제목이 **‘지금 입력된 상태’** 이고, 아래에 “지금 누른 값은 연습이에요.
     관람객 화면에는 …부터 보여요.” 안내가 붙습니다(누를 때 뜨는 알림도 “연습
     값이라 관람객 화면에는 안 보여요”). 운영 시간이 되어야 제목이 ‘관람객 화면에
     보이는 지금 상태’ 로 바뀝니다
   - 운영 포털 → **부스 현황**에서 그 부스 카드의 대기 표시와, 맨 위
     **‘부스 대기 입력’** 줄의 ‘입력 중’ 수(포털은 1분마다 다시 읽습니다)
   - 관람객 화면의 모양은 부스 Live 사이트 주소 끝에 `?demo` 를 붙여 봅니다
     (예시 부스라 늘 운영 중으로 보입니다)

   확인한 뒤 인쇄 화면의 **‘실시간 값 모두 지우기’** 를 누릅니다.
   모든 부스가 “정보 없음” 으로 돌아갑니다. SQL Editor 에서 하려면
   `delete from public.booth_live;` 입니다(단추와 같은 일). 입력 기록과
   열쇠는 지워지지 않으니 카드는 그대로 씁니다.
   다른 날 값은 원래 보이지 않으므로 둘째 날 아침에는 지울 필요가 없습니다.

#### 미리 보기 (`?demo=1`)

주소 끝에 `?demo=1`(`?demo` 도 같음)을 붙이면 예시 부스로 화면을 볼 수 있습니다.
운영 포털에서는 `visitor.html?demo=1` · `booth-ctrl.html?demo=1` · `print-qr.html?demo=1` ·
`admin.html?demo=1#booths` · `booth-admin.html?demo=1`(둘 다 관리자 로그인 필요),
부스 Live 사이트에서는 첫 화면 `?demo=1` · `booth-ctrl.html?demo=1` 입니다.
DB 에 쓰지도 읽지도 않고, 같은 브라우저 · 같은 사이트의 탭끼리만 맞춰집니다. 인쇄
화면은 카드마다 “협의용 예시 · 인쇄 금지” 가 찍힙니다. 세 화면 모두 맨 위 띠의 말은
‘협의용 예시 · 실제 행사 정보가 아닙니다.’ 로 같습니다.

관람객 화면에서는 이것이 **협의용 예시 화면**입니다. 실제 부스가 들어오면 어떤
모습이 되는지 행사 관계자와 함께 보며 협의할 때 씁니다.

- **들어가기**: 실제 부스가 한 곳도 없으면 첫 화면의 ‘부스 정보 준비 중’ 아래에
  **[협의용 예시 화면 보기]** 가 나옵니다. 실제 부스가 한 곳이라도 등록되면 이
  단추는 사라지고, `?demo=1` 주소로만 들어갑니다.
- **알아보기**: 맨 위에 줄무늬 띠 ‘협의용 예시 · 실제 행사 정보가 아닙니다.’ 가
  스크롤해도 붙어 있습니다. 운영 포털의 협의용 예시와 같은 말 · 같은 보라색입니다.
- **나가기**: 안내 상자와 목록 맨 아래의 **[실제 화면으로 돌아가기]**. 주소에서
  `?demo=1` 을 뗀 페이지를 새로 엽니다(같은 페이지에서 예시와 실제를 섞지 않음).
- **예시 부스 12곳**(`assets/mock-data.js`): 여유 0 · 5 · 10분, 보통 15 · 20 · 25분,
  혼잡 30 · 45분, 잠시 중단, 오늘 마감, 현황 미등록, 50분 전 입력이라 ‘확인 필요’ 로
  흐려진 부스. 기관은 ‘협의용 예시 학교 · 기관’, 구역은 ‘예시 구역 A · B · C’ 로만
  씁니다 — 실제 학교 · 확정 구역처럼 보이는 이름은 넣지 않습니다. 행사 이름 · 날짜 ·
  장소도 지어 넣지 않습니다(띠에는 ‘협의용 예시 화면’ 만).
- 검색 · 구역 탭 · 상태 숫자 · 대기 짧은 순 · 한눈에 · 펼침 · `?demo=1&b=A-04` 의
  ‘지금 계신 부스’ 가 실제 화면과 같은 코드로 움직입니다. 운영 시간과 관계없이 늘
  ‘운영 중’ 화면입니다.

관리자 화면의 **부스 협의용 예시**(`admin.html?demo=1#booths`)는 회의 · 관리자 교육용입니다.

- **들어가기**: 관리자로 로그인한 뒤, 실제 부스가 한 곳도 없으면 부스 화면의
  **[협의용 예시 화면 보기]**. 실제 부스가 생기면 단추는 사라지고 주소로만 들어갑니다.
  로그인 없이 `?demo=1` 을 붙여도 관리자 화면은 열리지 않습니다.
- **예시 12곳**: 위 예시 부스 11곳(같은 이름 · 번호) + 미배정 1곳. 공개 · 비공개 · 미배정 ·
  구역 비공개(예시 구역 D) · QR 발급됨 · 미발급 · 꺼짐 · ‘확인 필요’ 를 모두 담았습니다.
- **해 볼 수 있는 것**: 실제와 같은 검색 · 걸러 보기 · 수정 창 · 공개 규칙(같은 오류 문구),
  줄의 ⋯ 안에서 운영자 QR 발급 · 끄기 · 다시 켜기와 대기 입력(바로 · 5 · 15 · 30분 · 잠시
  중단 · 오늘 마감). 사진 칸과 ‘QR · PIN 관리’ 단추는 두지 않습니다(실제 보관함 · 열쇠).
- **DB 에 쓰지 않습니다**: 저장 · 공개 · 삭제 · QR · 대기 입력이 모두 메모리에서만 바뀌고,
  새로 고치면 처음 예시로 돌아갑니다. Supabase 요청은 관리자 확인(staff_profiles) 하나뿐입니다.
- **나가기**: 맨 위 띠의 **[실제 관리자 화면으로 돌아가기]**.

**부스 운영 현황 협의용 예시**(`booth-admin.html?demo=1`)도 같은 원칙입니다(관리자 로그인 필요 ·
Supabase 요청은 관리자 확인 하나 · 새로 고치면 처음 예시). 위 예시 부스로 여유 · 보통 · 혼잡(30 · 45분) ·

### 부스 운영자 PIN (QR 카드를 쓸 수 없을 때)

기본은 늘 **운영자 카드 QR** 입니다. PIN 은 카드를 못 받았거나 · 잃어버렸거나 · 카메라가 안 되거나 ·
담당자가 바뀌었을 때만 쓰는 보조 길입니다. DB 설정: `supabase/migration-booth-pin.sql`
(되돌리기 `rollback-booth-pin.sql`). QR 함수(`booth_ctrl_*`)와 `booth_access` 는 한 글자도 바꾸지 않습니다.

- **시작 화면**: 운영자 화면 주소(QR 없이 `…/booth-ctrl`)를 열면 막힌 안내 대신 **‘부스 운영을 시작해 주세요’**
  가 나옵니다. 위에서부터 ① QR 안내(휴대폰 기본 카메라로 카드 QR 촬영 · [QR 이용 안내]) ② **QR 카드가 없나요?**
  [부스 번호와 PIN으로 시작](PIN 스위치가 켜져 있을 때만) ③ 최근 운영한 부스 [이어서 열기](있을 때만)
  ④ 도움말(운영본부 문의). 화면 안 QR 스캐너는 두지 않습니다 — 기본 카메라 → `booth-ctrl#k=…` 그대로입니다.
- **운영자**: [부스 번호와 PIN으로 시작] → 구역 → 그 구역의 실제 부스(‘05 · 로봇 코딩’) → PIN 6자리.
  부스가 10곳 이상인 구역은 목록 위에 **‘부스 번호 또는 부스명으로 찾기’** 칸이 있습니다(`12` · `A12` · `A-12` →
  A-12 가 맨 위, 이름 일부도 됨, 다른 구역 번호를 치면 ‘다른 구역’ 으로 함께 보여 줌).
  QR 과 **같은 운영 화면**이 열리고, 아래에 ‘PIN으로 접속 중 · 오늘 24:00까지’(실제 세션 만료 시각) 와 **[이 기기에서 나가기]** 가
  붙습니다. 구역 · 부스는 관람객 화면과 같은 공개 목록에서 고릅니다(공개 · 배정된 부스만, 코드에 A · B 를 적어 두지 않음).
- **협의용 예시 PIN(4자리)**: `booth-ctrl.html?demo=1` 은 QR 안내에서 멈추지 않고 바로 구역 → 예시 부스 →
  **예시 PIN** 으로 운영 화면을 체험합니다(A-01 `0001` · A-04 `0004` · B-01 `0011` · C-01 `0021` — 구역 순서 × 10 +
  부스 번호, `mock-data.js` 의 `MOCK_DEMO_PIN`). 화면에 그 부스의 예시 PIN 이 보이고, 틀리면 ‘부스 번호나 PIN이
  맞지 않아요.’ 입니다. [예시 부스 바로 열기] 로 PIN 없이 A-01 을 열 수도 있습니다. 이 브라우저 안에서만 견주고
  서버 · `booth_pin` · `booth_session` · Vault 에 닿지 않습니다(Supabase 요청 0). 실제 PIN(6자리)과 입력 칸 ·
  코드 길이 다릅니다 — 주소의 `?demo` 만으로 정해집니다. 관리자 예시(`admin.html?demo=1`)도 같은 4자리를
  ‘예시 PIN 0001’ 로 보여 주고, PIN 발급 · 재발급 · 끄기는 메모리 안에서만 흉내 냅니다.
- **밝은 화면**: 운영자 화면은 낮 · 야외에서 숫자가 잘 보이도록 밝은 회백 바탕 · 흰 카드 · 남색 글자 · 보라 강조로
  바꿨습니다(관람객 화면 · 운영 포털과 같은 색 값). 대기 시간을 누르면 ‘✓ 15분으로 반영했습니다. / 관람객 화면에도
  곧 표시됩니다.’ 로 알립니다. 어두운 화면은 아직 없습니다(색은 토큰으로만 칠해 나중에 더할 수 있음).
  상태색은 관람객 화면과 같습니다 — 여유 `#08773F` · 보통 `#F4D400`(노랑 점 · 글자판, 글자는 남색) · 혼잡 `#E52521`
  · 중단 · 마감 회청색. 보라는 ‘지금 고른 대기 단추’, 주황(`--warn`)은 주의(연결 · 오래된 값), 진한 빨강(`--danger`)은
  오류와 [오늘 운영 마감] 같은 되돌리기 어려운 동작에만 씁니다(2026-10-05).
  숫자(대기 시간 · 부스 번호 · 예시 PIN)도 관람객 화면처럼 Pretendard 로 씁니다(고정폭 글꼴 없음; 대기 숫자만 자릿수
  폭을 맞추고 PIN 은 비례 숫자 — 아래 ‘PIN 숫자 모양’). 크기는 현재 대기(약 60px · 800) > 예시 PIN(32px · 700) >
  부스 이름(제목) > 부스 번호(15px 머리글) 순서이고, 보라는
  고른 값 · 주 단추 · 작은 강조에만 씁니다. 대기 단추는 ‘5분’ 처럼 한 줄로 쓰고, 잠시 중단 · 오늘 운영 마감은
  ‘운영 상태’ 로 떼어 둡니다. PIN 재발급과 개별 끄기는 서버가 같은 까닭으로 알려 와, 운영자 화면은 두 경우를
  한 문구(‘운영본부가 이 부스의 PIN을 바꿨습니다.’)로 함께 안내합니다.
- **같은 기기는 다시 묻지 않습니다**: PIN 은 어디에도 저장하지 않고, 서버가 준 임시 세션만 이 기기에
  둡니다. 세션은 **로그인 + 12시간과 그날 24:00(한국 시각) 중 이른 쪽**에 끝납니다(둘째 날은 다시 입력).
  행사 종료(`event_end`) + 12시간이 지나면 새 PIN 로그인은 받지 않습니다.
- **발급(관리자)**: 여러 부스는 관리자 → 부스 → **[QR · PIN 관리]** → **운영자 PIN 발급·관리**(아래 따로 설명),
  한 부스는 그 줄의 ⋯ → **[PIN 발급]**. 전화로 요청받으면 등록된 담당자 연락처로 되걸어 확인한 뒤 불러 줍니다.
  PIN 은 서버가 만들고(약한 PIN · 반복 · 연속 제외) **발급 창(결과 창)에서 한 번만** 보입니다 — 창을 닫으면 다시 볼 수
  없고, 잃어버리면 **재발급**. 관리자가 PIN 을 직접 정하지 않습니다. 미배정 부스는 발급할 수 없습니다.
- **재발급 · 끄기**: 재발급하면 옛 PIN 이 바로 실패하고 그 부스의 PIN 로그인이 모두 끝납니다. **[PIN 끄기]** 는
  새 로그인을 막고 열린 PIN 화면도 끝냅니다. 다시 켜기 = 새 PIN 발급. QR 은 어느 쪽에도 영향이 없고, QR 을
  바꾸거나 꺼도 PIN 은 그대로입니다(서로 독립).
- **전체 스위치**: 관리자 → 기본정보 → **PIN 보조 로그인 사용**(`settings.booth_pin_enabled`, 기본 꺼짐).
  끄면 ‘PIN으로 시작’ 단추가 사라지고 새 로그인 · 열린 PIN 화면이 바로 멈춥니다. QR 은 그대로입니다.
- **상태 표시**: 관리자 부스 목록에 `QR 발급됨 · 미발급 · 꺼짐` · `PIN 발급됨 · 미발급 · 꺼짐` · `PIN 로그인 n대` ·
  `PIN 실패 많음`(최근 1시간 10회 이상). 상태만 읽습니다(`admin_booth_credentials()` — 열쇠 · PIN · 해시 없음).
- **카드에 인쇄하지 않습니다**: 운영자 카드 · 부스 앞 안내 · 입구 포스터에 PIN 을 함께 찍지 않습니다. PIN 은 카드를 쓸 수
  없을 때를 위한 것이라 같은 종이에 두면 함께 잃어버립니다(둘을 한 장에 합친 카드를 잃으면 QR · PIN 을 모두 바꿔야
  하는 사고가 됩니다). PIN 은 발급 결과 창의 따로 된 **PIN 배부표**(관리자 전용)로만 인쇄합니다.
- **보안**: PIN 은 bcrypt(bf 10) + Vault 비밀(`booth_pin_pepper`)로 HMAC 한 해시만, 세션은 sha256 만 저장합니다.
  PIN 로그인은 QR 열쇠를 돌려주지 않고 `booth_access` 를 읽지도 않습니다. 세션 함수에는 부스 id 인자가 없습니다.
  대입은 잠그지 않고 늦춥니다 — 기기(10분 실패 5회 → 30초부터 두 배씩, 최대 10분) · 부스(15분 실패 10회 →
  그 부스 30초에 한 번) · 전체(1시간 실패 200회 → 전체 5초에 한 번). 운영자 화면은 ‘N초 뒤에 다시’ 로 보여 줍니다.
- **IP 층은 꺼져 있습니다**: IP 로도 늦추려면 Production 에서 어떤 헤더를 믿을 수 있는지 먼저 실측합니다
  (관리자로 로그인한 브라우저에서 `admin_booth_ip_probe()` 를 시험값 헤더와 함께 부름 — 원래 IP 는 돌려주지 않고
  헤더 이름과 시험값이 남는 자리만 알려 줍니다). 시험값이 그대로 남는 헤더는 위조할 수 있으니 쓰지 않습니다.
  믿을 수 있는 헤더가 확인될 때만 `update private.booth_pin_settings set ip_header = '…'` 로 켭니다.
  **2026-10-03 실측 결과 — 꺼 둠**: `X-Forwarded-For` 는 보낸 시험값이 맨 앞에 그대로 남고(첫 자리는 위조 가능),
  `X-Real-IP` 는 서버까지 오지 않으며, `CF-Connecting-IP` 를 직접 넣은 요청은 Cloudflare 가 403(error 1000)으로
  막습니다. 위조할 수 없는 자리(`cf-connecting-ip` · `x-forwarded-for:last`)는 있지만, 행사장 와이파이처럼 여러
  운영자가 한 IP 를 쓰면 IP 층(15분 실패 20회 → 15분)이 같은 망의 모든 PIN 로그인을 막을 수 있어 켜지 않았습니다.
  기기 · 부스 · 전체 층만으로 6자리 대입은 막힙니다.
- **기록**: `booth_auth_event`(성공 · 실패 · 제한 · 발급 · 끄기 · 세션 끊김). 원문 PIN · 세션 · QR 열쇠 · 해시 ·
  원래 IP · User-Agent 는 적지 않습니다. PIN 세션으로 넣은 대기 값은 `booth_live_log.session_id` 로 이어집니다.
- **되돌리기**: ① 한 부스 — PIN 끄기 ② 전체 즉시 — 스위치 끄기 ③ 화면 — 커밋 되돌리기
  ④ DB — `rollback-booth-pin.sql`(PIN 객체만 지우고 QR 함수 정의가 그대로인지 md5 로 확인).

#### QR · PIN 관리 → 운영자 PIN 발급·관리 (여러 부스)

관리자 → 부스 → **[QR · PIN 관리]**(주소는 예전 그대로 `print-qr.html`, 북마크 그대로) 맨 위의 접는 패널입니다.
아래 QR 인쇄(① 부스 운영자용 · ② 부스 앞 안내 · ③ 입구 포스터)와 **따로** 돕니다 — 이 패널의 체크는 PIN 작업 대상만
고르고, 카드의 ‘인쇄에 포함’ · 모두 선택 · 모두 해제와 상태 · 단추 · 이벤트가 모두 다릅니다. 패널은 인쇄 · ‘인쇄 화면으로
보기’ 에서 숨고, ② ③ 관람객 안내물에는 PIN 이 들어갈 자리가 없습니다.

- **현황**: 전체 배정 부스 · QR 발급됨 · PIN 발급됨 · 미발급 · 꺼짐(`admin_booth_credentials()` 로 지금 데이터에서 셈).
  상태를 읽지 못하면 0 으로 적지 않고 **‘상태 확인 불가’** 로 적고 발급 단추를 잠급니다. 미배정 부스는 목록에서 뺍니다.
  PIN 보조 로그인 스위치가 꺼져 있으면(발급과 별개로 로그인이 안 됨), [예시] 공통 PIN 스위치가 켜져 있으면(부스별 PIN 을
  발급해도 그 부스는 123456 으로도 열림 — **실제 행사 전에 끄기**) 안내만 합니다. 설정은 바꾸지 않습니다.
- **고르기**: 부스마다 체크(부스 id 로 기억), 구역 칩 · 찾기, ‘보이는 부스 모두 선택’(전체 · 그 구역 · 찾은 결과), 선택 해제,
  ‘선택 n곳 · 발급 대상 · 재발급 대상’. **찾기 · 구역을 바꾸면 선택이 풀립니다**(보이지 않는 부스가 고른 채 남지 않게).
- **[선택 PIN 발급]**: PIN 미발급 → 새로 발급, PIN 꺼짐 → 새 PIN 으로 다시 켜기, **이미 PIN 이 있는 부스는 제외**.
  **[선택 PIN 재발급]**: PIN 이 켜진 부스만. 기존 PIN 이 바로 무효가 되고 그 PIN 으로 연 기기가 로그아웃됩니다(QR · 다른
  부스는 그대로). 2곳 이상이면 확인 칸에 **재발급** 이라고 적어야 실행됩니다.
- **누르면**: 서버 상태를 새로 읽어 대상을 다시 세고(‘선택 10곳 · 신규 6곳 · 꺼진 PIN 2곳 · 기존 정상 PIN 2곳 제외’),
  확인 창에서 대상을 고정합니다. 부스 하나씩 차례로 보내고(‘17 / 50 처리 중’, [남은 부스 멈추기]) 그동안 목록 · 찾기 ·
  단추를 잠급니다.
- **결과 창**: 부스마다 PIN(‘381 742’) · **실패**(서버가 거절 — 바뀐 것 없음) · **결과 확인 필요**(응답을 받지 못함 — 서버에서
  PIN 이 바뀌었을 수 있고 그 PIN 은 다시 볼 수 없음) · 건너뜀 · 실행 안 함. ‘결과 확인 필요’ 가 나오면 남은 부스는 보내지
  않습니다. **자동으로 다시 보내지 않습니다** — 창을 닫으면 패널에 PIN 없는 요약과 [이 n곳 다시 고르기] 가 남고, 다시 누르면
  늘 서버 상태부터 다시 읽습니다(그 사이 PIN 이 생긴 부스는 ‘발급’ 에서 빠지고 재발급은 관리자가 따로 정함).
- **CSV 저장**: 누를 때만 이 컴퓨터로 내려받습니다(서버 · 저장소에 올리지 않음). 칸: 부스번호 · 부스명 · 운영기관 · 구역 · PIN,
  UTF-8 BOM, 모든 칸을 큰따옴표로 감쌈, `= + - @` 로 시작하는 글자 칸은 앞에 `'` 를 붙여 수식으로 읽히지 않게 합니다.

  0으로 시작하는 PIN 8개로 확인). 띄어 쓴 PIN 을 운영자는 숫자 6자리로 그대로 누르면 됩니다.
  **PIN 목록은 운영자 배부용으로만 쓰고, 공개 폴더나 단체 대화방에 올리지 마세요.**
- **PIN 배부표 인쇄**: 관리자 전용 A4 세로 쪽지(부스번호 · 부스명 · 기관 · 구역 · PIN · 운영자 화면 주소), 선을 따라 잘라 그
  부스 담당자에게만 줍니다. QR 카드와 섞지 않습니다.
- **닫기**: CSV 저장도 인쇄도 하지 않았으면 ‘PIN을 저장하지 않고 닫을까요? 이 PIN은 다시 확인할 수 없습니다.’ 를 한 번 더
  묻습니다. 닫으면 PIN 을 담은 변수 · 화면 · 배부표를 비웁니다. PIN 은 저장소 · 주소 · 쿠키 · 콘솔 어디에도 두지 않으므로
  **새로 고침 · 브라우저 종료 · 다른 탭에서 로그아웃하면 결과 창의 PIN 을 잃습니다**(그 부스는 다시 발급).
- **PIN 이 새거나 잃어버렸을 때**: 한 곳 — 그 부스만 체크 → [선택 PIN 재발급] → 새 PIN 을 담당자에게. 그 부스 QR 과 다른
  부스는 그대로입니다. 여러 곳 — 구역 칩으로 좁혀 해당 부스만 체크 → [선택 PIN 재발급](재발급 입력 확인).
- **동시 작업**: 지금 서버 함수(`admin_issue_booth_pin`)는 조건 없이 발급합니다. 그래서 이 화면은 부스마다 보내기 직전에
  상태를 다시 읽지만, 그 확인과 발급 사이에 다른 관리자가 같은 부스 PIN 을 발급하면 나중 요청이 앞의 PIN 을 바꿀 수 있습니다
  (확인 창에 이 한계를 적고, 그 부스에 PIN 로그인 기기가 있었으면 결과에 ‘예상과 달리 n대 로그아웃’ 으로 알립니다).
  **PIN 작업은 한 사람이 맡으세요.** 서버에서 이 틈을 닫는 함수가 `supabase/migration-booth-pin-checked.sql`
  (**초안 · 미적용**, 되돌리기 `rollback-booth-pin-checked.sql`)입니다 — 적용하면 화면이 저절로 그 함수를 써서, 상태가
  다르면 서버가 아무것도 바꾸지 않고 거절합니다(같은 계정이 방금 바꾼 경우는 ‘결과 확인 필요’ 로 따로 알림).
- **협의용 예시**(`print-qr.html?demo=1`): 서버 함수를 부르지 않고 이 화면 안에서만 흉내 냅니다(예시 PIN 4자리).

### 부스 운영 현황 (행사 당일 콘솔 · `booth-admin.html`)

정보 설정(구역 · 부스 등록 · 공개 · 기관 · 담당자 · QR · PIN)은 `admin.html`, **행사 당일 “지금 어느 부스가
문제인가”** 는 `booth-admin.html` 입니다. 운영 포털(GitHub Pages)에만 있고 부스 Live 사이트에는 없습니다.
관리자 화면과 같은 로그인 · 같은 문지기(관리자만)입니다. 관리자 화면의 메뉴 끝 **행사 당일 · 부스 운영 현황**,
부스 화면의 **[부스 운영 현황]** 으로 들어갑니다.

- **맨 위 숫자 = 걸러 보기**: 전체 · 혼잡 · 확인 필요 · 미입력 · 일시 중단 · 운영 종료(문제가 있을 때만
  QR 준비 필요 · PIN 확인). 그 아래는 검색(부스번호 · 부스명 · 기관 · 프로그램) · 구역 · 정렬(운영 우선 · 부스번호 ·
  대기시간 높은 순 · 최근 입력 오래된 순) 셋뿐이고, 비공개 · 미배정 부스 보기는 결과 줄 오른쪽에 있습니다. ‘운영 우선’ 은 확인 필요 → 미입력 → 혼잡 → 잠시 중단 → 운영 중 → 오늘 마감 순
  (마감은 맨 아래).
- **부스 한 곳 = 한 줄**(휴대폰 약 72px · PC 약 60px): 부스 번호 · 이름 · 운영 상태 · 대기 시간 · 마지막 입력 ·
  확인할 것. 80곳이어도 한 화면에 휴대폰 8줄 · PC 13줄쯤 보입니다. 검색 · 구역 · 정렬 줄(PC 는 표 머리까지)은
  내려도 위에 붙어 있고, 숫자로 걸러 보는 중이면 그 아래에 ‘○○만 보는 중 · N곳 [전체 보기]’ 가 뜹니다.
- **정상은 조용히, 이상만 표시**: ‘QR 정상 · PIN 정상’ 은 쓰지 않고 QR 미발급 · QR 꺼짐 · PIN 미발급 · PIN 꺼짐 ·
  PIN 실패 많음 · 확인 필요(오래된 값)만 작은 표시로 붙입니다. 단추도 확인이 필요한 부스(오래된 값 · QR/PIN
  문제)는 진한 **[확인·수정]**, 미입력은 옅은 [입력], 나머지는 테두리만 있는 [수정]입니다.
- 운영기관 · 프로그램 · 구역 · 접속 상태 · 마지막 입력(운영자 QR · 운영자 PIN · 관리자 중 누가 넣었는지)은 줄을
  누르면(휴대폰) · ⋯ 를 누르면(PC) 펼쳐집니다.
- 혼잡도 · ‘확인 필요’(30분 넘게 그대로, 마감 제외) · ‘N분 전’ 은 관람객 · 운영자 화면과 같은 공통 엔진
  (`booth-core.js`) 규칙을 씁니다. 검색은 부스 번호를 `B-03` · `b03` · `b3` · `b-3` 어느 꼴로 쳐도 찾습니다.
- **[현황 수정]**: 바로 · 5 · 10 · 15 · 20 · 30 · 45 · 60분 · 잠시 중단 · 오늘 마감 · 값 지우기. 기존
  `admin_set_booth_live` 를 그대로 씁니다(기록 source ‘admin’). 새 공개 쓰기 함수는 없습니다. 모든 부스 값을
  한꺼번에 지우는 일(`admin_reset_booth_live`)은 이 화면에 두지 않습니다 — QR 인쇄 화면에만 있습니다.
- **다시 읽기**: 대기 값 15초마다, 부스 · 구역 · QR · PIN 상태 60초마다(화면이 가려지면 쉼). Realtime 은 쓰지 않습니다.
- **구역 현황**: 구역마다 운영 중 · 혼잡 · 확인 필요 · 미입력 · 중단 · 마감 수와 가장 긴 대기. 누르면 그 구역만 봅니다.
- 부스 정보 · PIN 은 펼친 줄의 **[부스 정보 관리] · [PIN 관리]**(관리자 화면의 그 부스로), QR 은 **[QR 관리]**(인쇄 화면).

### 운영 준비용 예시 부스 (Production)

협의 · 리허설 동안 Production 에 A~J 10개 구역 · 50개 부스(구역마다 5곳 — 처음 12곳 A-01 ~ C-04 에 2026-10-05
내부 리허설용 38곳을 더함)를 **공개 상태**로 두고, 실제 행사 정보가 정해지면 지우지 않고 하나씩 고쳐 씁니다.
따로 표시 칸이나 migration 은 없고, **운영기관 이름이 `[예시]` 로 시작하면 예시 부스**로 봅니다
(`BoothCore.isSample` · 관리자 `isSampleBooth` · 서버 `private.booth_common_pin_target`).
A~J 는 리허설용 임시 구역입니다(이름 'A구역' … 'J구역', 정해진 뜻 없음). 실제 구역이 정해지면 구역도 지우지 않고
이름 · 순서를 고쳐 쓰거나, 남는 구역은 부스를 옮긴 뒤 비공개로 둡니다.
50곳은 관람객 화면이 30곳을 넘을 때의 모양(전체 + 한눈에 = 구역 요약, 구역 선택 패널, 검색)을 실제 데이터로
보기 위한 크기입니다. 소개용 `/example/` 화면은 이와 별개로 짧은 축약 화면 그대로 둡니다.

| 무엇을 보여 줄 때 | 쓰는 것 |
|---|---|
| 일반 사용자 · 협의 자리에서 보여 주는 대표 예시 | Production 의 **운영 준비용 예시** 부스(이 절) · **공통 PIN 123456** |
| 개발 · 테스트 · 설명용 안전한 샌드박스 | `?demo=1` **협의용 예시**(브라우저 안의 가짜 부스 · 서버 요청 0 · 예시 PIN 4자리 0001 · 0002 …) |
| 실제 행사 부스 | 부스별 **랜덤 6자리 PIN**(관리자가 발급 · 한 번만 보임) 또는 QR |

- **외부 화면은 깔끔하게, 관리 화면은 분명하게**(2026-10-04~): `[예시]` 는 판별용 내부 표시라 DB 에는 그대로 두고, 화면에
  보일 때만 `displayOrganization(org)`(`BoothCore` · admin.js · portal.js — 같은 규칙)로 떼어 냅니다(‘[예시] 인천미래초’ →
  ‘인천미래초’). 관람객 · 운영자 · booth-admin · 관리자 목록 · QR 인쇄물 · 포털 부스 목록이 모두 같고, 검색도 뗀 이름으로
  합니다. **관리자 → 부스 [수정] 칸에는 원래 값(`[예시] …`)이 그대로 나옵니다** — 지우고 저장하면 그 부스는 실제 부스가 됩니다.
- **관람객 화면**: 예시 안내는 없습니다. 행사 전에는 원래 대기 값을 감추지만, **예시 부스의 값만은 미리 보여 줍니다**
  (`BoothCore.samplePreview` — phase `before` 일 때만). 행사 날부터는 예시여도 원래 규칙입니다.
- **부스 운영자 화면**: 예시 안내는 없습니다. 공통 PIN 이 켜진 예시 부스의 PIN 칸만 ‘운영자 PIN · 현재 부스의 PIN은
  123456입니다.’ 로 안내합니다. 행사 전 예시 부스의 저장 알림은 운영 중과 같은 “관람객 화면에도 곧 표시됩니다.”,
  실제 부스는 지금처럼 ‘연습 값’ 으로 알립니다.
- **관리 화면(관리자 · booth-admin · QR 인쇄)**: 기관명에는 `[예시]` 를 붙이지 않고, 예시 부스에 테두리만 있는 작은 **예시** 표를
  하나 답니다(관리자 부스 줄 · booth-admin 부스 이름 뒤 · QR 인쇄 화면의 카드 아래 상태 줄). QR 인쇄 화면은 인쇄할 장 수 옆에
  ‘예시 부스 N장 포함’ 도 알립니다. 이 표시는 화면에만 있고 종이에는 찍히지 않으며, 기관에서 `[예시]` 를 지우면 저절로 사라집니다.
  규칙 설명은 관리자 → 부스 화면 설명 한 줄에만 둡니다(“[예시] 표시가 있는 운영기관은 준비 기간 공통 PIN 및 예시 현황 채우기 · 비우기
  대상입니다.”). 켜고 끄기는 기본정보의 스위치, booth-admin 의 **예시 현황 채우기 · 비우기** 는 그대로입니다.
- **공통 PIN 123456**(`supabase/migration-booth-example-pin.sql`): 예시 부스는 부스마다 PIN 을 발급하지 않아도 운영자
  화면에서 구역 → 부스 → **123456** 으로 들어갑니다. 서버(`booth_pin_login`)가 로그인하는 순간 **PIN 보조 로그인 ·
  공통 PIN 스위치(`settings.booth_sample_common_pin_enabled`) · 부스 공개 · 구역 공개 · 기관 `[예시]`** 를 모두 확인한 뒤
  보통의 PIN 세션을 엽니다(운영 화면 · 기록은 실제 PIN 과 같음, 기록 source 도 PIN). 화면은 값을 안내만 합니다.
  - 실제 PIN 은 그대로입니다 — bcrypt bf10 + Vault pepper · 약한 PIN 거르기(123456 은 실제 PIN 으로 만들어지지 않음) ·
    횟수 제한 · 세션 규칙. 공통 PIN 은 실제 PIN 을 먼저 견준 뒤에만 보고, 틀린 PIN 은 같은 횟수 제한에 걸립니다.
  - 공통 PIN 으로 연 세션은 표시해 두고(`booth_session.via_common_pin`) 쓸 때마다 조건을 다시 봅니다. 기관에서
    `[예시]` 를 지우거나 스위치를 끄면 **그 순간** 공통 PIN 로그인과 열린 공통 PIN 화면이 멈춥니다(“운영본부가 이 부스의
    PIN을 바꿨습니다” 화면). 그 부스에 실제 PIN 이 있으면 실제 PIN 은 계속 됩니다.
  - 보안 기록에는 원문 대신 `detail = 'common_pin'` 만 남깁니다. 관람객 화면에는 공통 PIN 을 보여 주지 않습니다.
  - 켜고 끄기: 관리자 → 기본정보 → **부스 운영자 PIN · 운영 준비용 예시 부스 공통 PIN**(또는
    `update public.settings set booth_sample_common_pin_enabled = false;`). **실제 행사로 넘어가기 전에 끕니다.**
- 대기 값은 실제와 같은 규칙입니다 — 30분 넘게 그대로면 흐리게(‘확인 필요’), 한국 날짜가 바뀌면 ‘미입력’.
  시연 전에는 아래 **예시 현황 채우기** 로 한 번에 다시 넣고, **예시 현황 비우기** 로 한 번에 비웁니다(부스 하나만이면 **[현황 수정]**).
- **실제 부스로 바꿀 때**: 지우고 다시 만들지 않습니다. 관리자 → 부스 → **[수정]** 으로 같은 줄(UUID 유지)의
  부스명 · 운영기관 · 프로그램 · 담당자를 고칩니다. 운영기관에서 `[예시]` 를 지우면 그 부스의 미리 보기 · 공통 PIN ·
  예시 현황 채우기 · 비우기 대상이 함께 빠집니다(코드 수정 · 배포 없음). 순서는 아래 체크리스트대로 합니다.

#### `[예시]` → 실제 부스 전환 체크리스트

부스 하나씩, 실제 자료가 들어온 부스부터 합니다. 리허설이 끝났다고 50곳을 한꺼번에 지우지 않습니다.

1. **실제 부스명** 입력 — 관리자 → 부스 → 그 줄 **[수정]**.
2. **실제 운영기관** 입력 — 같은 칸에서 `[예시] …` 를 실제 이름으로 바꿉니다(5번과 같은 저장).
3. **실제 프로그램 · 설명 · 기관 구분** 입력.
4. **실제 구역 · 번호** 확인 — 바꾸면 표시 번호(A-01 등)는 DB 가 새로 만듭니다. 같은 구역 · 번호가 이미 있으면 저장이 막히니
   먼저 비운 자리로 옮깁니다. 부스의 진짜 이름표는 UUID 라 번호를 바꿔도 같은 부스입니다.
5. **`[예시]` 표시 제거** — 저장하는 순간 미리 보기 · 공통 PIN 123456 · 예시 현황 채우기 · 비우기 대상에서 바로 빠집니다.
6. **리허설 대기 값 지우기** — booth-admin 그 부스의 **[현황 수정] → 값 지우기**(행사 전 실제 부스는 관람객 화면에 값이 안
   보이지만, 리허설 값을 남겨 두지 않습니다).
7. **예시 세션 정리** — 5번으로 공통 PIN 으로 열린 운영자 화면은 저절로 멈춥니다(“운영본부가 이 부스의 PIN을 바꿨습니다”).
   그 부스에 리허설 때 낸 실제 PIN 이 있으면 **[PIN 재발급]** 으로 그 PIN 세션도 끊습니다.
8. **QR · PIN 정책 확인** — 리허설 때 카드 사진이 돌았을 수 있으면 인쇄 화면의 **‘열쇠 바꾸기’** 로 QR 을 새로 내고 카드를
   다시 인쇄합니다(권장). PIN 은 실제 담당자가 정해지면 **[PIN 발급 · 재발급]**.
9. **공개 상태 최종 확인** — 부스 공개 · 구역 공개 · 구역 · 번호.
10. **화면 확인** — 관람객 화면에서 이름 · 기관 · 번호, 운영자 화면에서 QR(또는 PIN) 진입 · 대기 입력.

**행사 직전 마지막 확인(한 번만)**: 관리자 → 기본정보 → **운영 준비용 예시 부스 공통 PIN 끄기**
(`settings.booth_sample_common_pin_enabled = false`). 끄면 남은 `[예시]` 부스도 123456 으로 열리지 않고, 열려 있던 공통 PIN
화면도 멈춥니다. 같은 때 `/example/` 소개 화면의 PIN 123456 안내 줄도 고치거나 뺍니다. 행사에 쓰지 않을 `[예시]` 부스가
남았으면 비공개로 돌립니다(지우지 않음).

### 준비 기간 예시 현황: 채우기 · 비우기

`booth-admin.html` 머리의 두 단추입니다. 공개된 `[예시]` 부스가 있을 때만 보이고, 협의용 예시(`?demo=1`)에는 없습니다.
**이미 예시로 판별되는 부스의 지금 대기 현황만** 채우거나 비웁니다. 부스를 예시로 만들거나 `[예시]` 를 붙이고 떼는 기능은
없습니다 — 예시 여부는 DB 의 운영기관 이름(`[예시]` 로 시작)만으로 정해지고, 관리자 → 부스 → [수정] 에서만 바뀝니다.
실제 부스에는 적용되지 않습니다.

- **[예시 현황 채우기]** — 확인 창 “예시 현황을 채울까요? / 현재 공개된 예시 부스 N곳에 다양한 대기 상태를 입력합니다.
  실제 부스에는 적용되지 않습니다.” [취소 / 채우기] 뒤에 아래 비율로 값을 넣습니다.
- **[예시 현황 비우기]** — 확인 창 “예시 현황을 비울까요? / 현재 공개된 예시 부스 N곳의 대기 상태를 모두 미입력으로
  되돌립니다. 실제 부스에는 적용되지 않습니다.” [취소 / 비우기] 뒤에 대기 상태를 지워 입력 전(관리 화면 ‘미입력’,
  관람객 화면 ‘정보 없음’)으로 되돌립니다. 다른 예시 값을 넣지 않습니다.
- 확인 창의 N 은 단추를 누르는 순간 서버에서 다시 읽은 대상 수입니다.

| 상태 | 비율(50곳일 때) | 대기 값 |
|---|---|---|
| 여유 | 38% (19곳) | 바로 · 5분 · 10분 |
| 보통 | 30% (15곳) | 15분 · 20분 |
| 혼잡 | 20% (10곳) | 30분 · 45분 · 60분 |
| 잠시 중단 | 6% (3곳) | — |
| 오늘 마감 | 6% (3곳) | — |

예시 부스가 몇 곳이든 이 비율로 나눕니다(12곳이면 4 · 4 · 2 · 1 · 1, 100곳이면 38 · 30 · 20 · 6 · 6). 부스는 **UUID 순서**로
줄 세워 차례로 받으므로 다시 눌러도 같은 부스에 같은 값이 들어가고(리허설 · 점검 때 견주기 쉬움), A-01 같은 표시 번호를
바꿔도 결과는 같습니다. 같은 상태가 줄줄이 붙지 않게 섞어서 나눕니다(`booth-admin.js` 의 `EXAMPLE_MIX` · `examplePlan`).
혼잡도는 늘 서버가 대기 시간으로 정합니다(10분 이하 여유 · 25분 이하 보통 · 그 위 혼잡) — 위 값은 그 규칙에 맞춰 고른 것이고,
화면이 혼잡도를 따로 정하지 않습니다.

- 누르는 순간 부스 목록을 서버에서 다시 읽어 확인 창의 N 을 세고, [채우기 · 비우기] 를 누른 뒤 **한 번 더** 읽어
  **기관이 `[예시]` 로 시작 · 공개 · 구역 공개** 인 부스에만 부스 UUID 로 보냅니다. 확인 창을 연 사이 `[예시]` 를 지운 부스도 빠집니다.
- 4개씩 나눠 보내고 단추에 “채우는 중… 12/50” 처럼 진행을 보여 줍니다(50곳 약 3~5초).
- 새 DB 함수는 없습니다. 부스마다 관리자 긴급 수정과 같은 `admin_set_booth_live` 를 부릅니다(채우기 `open` · `pause` ·
  `closed`, 비우기 `clear` — ‘값 지우기’ 와 같은 길, 기록 source ‘admin’). 모든 부스를 지우는 `admin_reset_booth_live` 는 쓰지 않습니다.
- 끝나면 바로 다시 읽어 요약 · 카드를 새로 그리고 “예시 부스 N곳에 현황을 채웠습니다.” / “예시 부스 N곳의 현황을 비웠습니다.” 를
  띄웁니다. 일부가 실패하면 “성공 49곳 · 실패 1곳 (B-02)” 처럼 알립니다(실패가 6곳 이상이면 앞 5곳과 ‘외 N곳’).
- 관람객 · 부스 운영자 화면에는 ‘예시’ 라는 말이 나가지 않습니다(값만 보입니다). 관리 화면의 작은 **예시** 표는 그대로입니다.
- 30분 ‘확인 필요’ · 자정 초기화 · 행사 시간 규칙은 그대로입니다. 바뀌는 것은 예시 부스의 `booth_live` 한 줄뿐이고, 부스명 ·
  운영기관 · 구역 · 공개 여부 · `[예시]` 표시 · QR · PIN · 세션 · 공통 PIN 은 건드리지 않습니다.

**PIN 숫자 모양**(부스 운영자 화면의 예시 PIN · PIN 칸, 관리자 화면의 발급 PIN): Pretendard 700 · 남색 · **비례 숫자** ·
자간 0.03em. 자릿수 폭을 맞추는 `tabular-nums` 는 ‘1’ 을 넓혀 0001 이 고정폭 글꼴처럼 띄엄띄엄 보이므로, 값이 바뀌며
옆 글이 밀리면 안 되는 현재 대기 숫자에만 씁니다. PIN 입력은 자릿수만큼 칸(4 · 6, 6자리는 3 · 3 묶음)을 그리고 실제
글칸은 그 위에 투명하게 겹쳐 둡니다(붙여넣기 · 숫자 자판 · 화면 읽기 프로그램은 보통 글칸 그대로).

### 결과 보고

부스별 · 시간대별 평균 대기 시간과 입력 횟수입니다(SQL Editor).

```sql
select coalesce(nullif(b.code, ''),
                b.zone_key || '-' || lpad(b.no::text, greatest(2, length(b.no::text)), '0')) as code,
       b.name,
       date_trunc('hour', l.created_at at time zone 'Asia/Seoul') as 시각,
       round(avg(l.wait_minutes) filter (where l.congestion in ('여유', '보통', '혼잡'))) as 평균대기,
       count(*) filter (where l.congestion in ('여유', '보통', '혼잡')) as 입력수,
       count(*) filter (where l.congestion in ('중단', '마감')) as 중단마감수
  from public.booth_live_log l
  join public.booths b on b.id = l.booth_id
 where l.source = 'set'
 group by 1, 2, 3
 order by 1, 3;
```

`supabase/migration-booth-live.sql` 7번의 보고 쿼리와 같습니다.

- `source = 'set'` 은 부스 선생님이 대기 시간 · 상태를 누른 기록만 셉니다
  (‘변동 없음 · 지금 확인’ 은 `touch`, 운영본부가 직접 고친 값은 `admin` 으로
  따로 남습니다).
- ‘잠시 중단’ · ‘오늘 마감’ 도 대기 0분으로 기록됩니다. 평균에 넣으면 마감을
  누른 마지막 시간대마다 평균이 0 쪽으로 끌려 내려가므로, **평균대기 · 입력수는
  운영 중(여유 · 보통 · 혼잡) 값만** 세고 중단 · 마감은 **중단마감수**로 따로
  셉니다. 중단만 있던 시간대도 빠지지 않고 평균대기가 빈 칸으로 나옵니다.
- 평균은 누른 횟수 기준입니다(머문 시간으로 가중하지 않습니다).
- 코드가 비어 있는 부스는 ‘구역-번호’(예: `A-03`)로 보입니다.

### 주의

- **QR 을 인쇄한 뒤에는 부스를 지웠다가 다시 만들지 마세요.** 부스를 지우면 그
  부스의 열쇠도 함께 지워져(cascade) 인쇄한 운영자 카드가 바로 죽고, 부스 앞
  안내 QR 도 “이 안내 QR의 부스를 찾지 못했어요” 가 됩니다. 운영자료를 다시 넣을 때도 기존
  부스는 그 자리에서 고치고(UPDATE), 새 부스만 더합니다.
- 부스 번호 · 이름을 고치는 것은 괜찮습니다. QR 은 번호가 아니라 부스 id 와
  열쇠를 가리킵니다. 다만 이미 인쇄한 카드에 찍힌 번호는 예전 그대로입니다.
- 관람객 화면의 대기 현황은 **주기적으로** 갱신됩니다. 누르자마자 바뀌지 않는 것은
  고장이 아니라 설계입니다(위 ‘Realtime 은 쓰지 않습니다’).
- 같은 부스를 기기 두 대에서 열어도 됩니다. 나중에 누른 값이 남고, 다른
  기기에서 바꾸면 운영자 화면에 알림이 뜹니다.

## 배포

**지금 쓰는 배포처는 둘입니다.** 같은 저장소를 브랜치로 나눠 씁니다
(2026-10-04 GitHub Actions 실행 기록 · Vercel 배포 목록으로 확인).

| 사이트 | 호스팅 | 배포하는 브랜치 | 주소 | 올라가는 것 |
|---|---|---|---|---|
| 운영 포털 (포털 · 관리자 · 부스 운영 현황 · QR 인쇄) | **GitHub Pages** (Deploy from a branch · Jekyll) | `main` (저장소 뿌리) | https://sinjhon1245-cell.github.io/incheon-festival/ · `…/admin.html` · `…/booth-admin.html` · `…/print-qr.html` | 저장소 뿌리 파일에서 `_config.yml` 의 `exclude` 와 점(.)으로 시작하는 것을 뺀 나머지 |
| 부스 Live 사이트 (관람객 화면 · 부스 운영자 화면) | **Vercel** 프로젝트 `incheon-live` (Root Directory `live`) | Production = `booth-live` | https://incheon-live.vercel.app/ · `…/booth-ctrl` · `…/example` | `live/build.sh` 가 만든 `live/dist` |

- **GitHub Pages** 는 저장소 설정(Settings → Pages)의 ‘Deploy from a branch’ 로 돌고, Actions 에는
  GitHub 가 만든 `pages build and deployment` 하나만 보입니다(`.github/workflows` 파일은 없습니다).
  `main` 에 push 하면 몇 십 초 뒤 새 판이 올라갑니다. 빌드 명령 · 환경변수는 없고 Supabase 연결
  정보는 `assets/config.js` 로 함께 올라갑니다. 빠지는 것: `scripts` · `supabase` · `design` ·
  `live` · `TASK.md` · `README.md` · `dev-server.*` · `netlify.toml` 과 `.claude` · `.mcp.json` 같은
  점 파일. `visitor.html` · `booth-ctrl.html` 도 함께 올라가지만 `?demo` 미리 보기용 사본이고, 종이
  QR 은 그쪽을 가리키지 않습니다.
- **Vercel** 은 `booth-live` push 를 Production 으로, 그 밖의 브랜치(`main` 포함) push 를 미리 보기
  (Preview) 로 배포합니다. 미리 보기 주소는 Vercel 로그인이 있어야 열리므로 관람객 주소로 쓰지
  않습니다. **부스 Live 사이트를 바꾸려면 `booth-live` 에 push** 해야 합니다(`main` 만 올리면 운영
  포털만 바뀝니다). 지금은 두 브랜치를 같은 커밋으로 맞춰 둡니다.
- **Netlify 는 지금 배포처가 아닙니다.** 저장소의 `netlify.toml` · `live/netlify.toml` 은 처음
  Netlify 로 올리던 때의 설정을 예비로 남긴 것입니다. GitHub Pages 와 Vercel 은 이 두 파일을 읽지
  않으므로(Pages 배포본에서는 `_config.yml` 이 빼고, Vercel 은 `live/vercel.json` 만 읽음) 있어도
  지금 배포에 영향이 없습니다. 예전 주소 `incheon-aisw-festival.netlify.app` 도 운영에 쓰지 않습니다
  (Netlify 계정에 예전 사이트가 남아 저장소와 이어져 있는지는 이 저장소에서 알 수 없으니 Netlify
  대시보드에서 확인합니다. `print-qr.html` 은 그 주소도 운영 포털로 보고 QR 주소로 쓰지 못하게 막습니다).

GitHub Pages 에는 `netlify.toml` 의 헤더 · 다시쓰기가 붙지 않습니다. 그래서 운영 포털에서는

- `/admin` 다시쓰기가 없습니다 → 관리자 화면은 `…/admin.html` 로 엽니다
- `X-Robots-Tag` 헤더가 붙지 않습니다 → 검색 차단은 `robots.txt` 와
  각 페이지의 `<meta name="robots" content="noindex, nofollow">` 가 맡습니다
- `admin.html` · `booth-admin.html` · `print-qr.html` 에 저장 금지(no-store) 헤더가 붙지 않습니다 →
  세 화면은 뒤로가기 캐시(bfcache)에서 되살아나면 스스로 새로 고쳐 로그인부터 다시 확인합니다
  (`pageshow` 처리). 그래도 인쇄를 마치면 로그아웃하고 창을 닫습니다

부스 Live 사이트의 헤더 · 다시쓰기 · 빌드를 건너뛸 조건은 `live/vercel.json` 이 정합니다.
`live/netlify.toml` 은 같은 일을 하는 예비 판입니다. `vercel.json` 은 JSON 이라 설명을 적을 수
없어 두 파일을 견준 표를 여기 둡니다.

| `live/netlify.toml` | `live/vercel.json` | 다른 점 |
|---|---|---|
| `command` · `publish` | `buildCommand` · `outputDirectory` (+ `framework: null` · `installCommand: ""`) | 없음 |
| `/visitor.html` → `/index.html` (200) | `rewrites` | 없음. 둘 다 같은 이름의 파일이 없을 때만 이어 주고, `?demo` 가 남습니다 |
| Netlify 가 `/booth-ctrl` 에도 `booth-ctrl.html` 을 내줌 | `rewrites` 로 `/booth-ctrl` → `/booth-ctrl.html` | Vercel 은 따로 적어야 합니다(`cleanUrls` 는 `.html` 주소를 다른 주소로 넘기므로 쓰지 않음) |
| `/*` 보안 헤더 다섯 | `/(.*)` 에 넷 + `Referrer-Policy` 는 운영자 화면 두 주소를 뺀 나머지에 | 같은 헤더를 두 규칙이 겹쳐 주지 않도록 나눴습니다. 결과는 같습니다 |
| `/assets/*` · `/index.html` no-cache | 같은 둘 + `/` · `/visitor.html` | 관람객 QR 이 여는 `/?b=…` 와 `/visitor.html` 도 같은 캐시 헤더를 받게 했습니다(Vercel 헤더는 다시쓰기 전 주소로 붙음) |
| `/booth-ctrl.html` · `/booth-ctrl` no-referrer · no-cache | 같음 | 없음 |
| `ignore` (Netlify 변수 `CACHED_COMMIT_REF`) | `ignoreCommand` (Vercel 변수 `VERCEL_GIT_PREVIOUS_SHA`) | Vercel 은 256자 제한이 있어 `assets/` 의 파일 다섯 대신 `assets/` 폴더 전체와 비교합니다. 포털 스크립트만 바뀐 push 에도 한 번 더 빌드할 뿐, 빠뜨리는 쪽으로 틀리지는 않습니다 |

부스 Live 사이트는 `live/build.sh` 가 배포 때마다 `assets/config.js` 에서 필요한 값
(연결 값 넷 · `boothHelpLine`)만 뽑아 자기 설정 파일을 만듭니다. 그래서 그 값이 읽을
수 없는 모양이면 빌드가 멈추고(`빌드 중단: …`), 두 화면과 관계없는 파일만 바뀐
push 는 건너뜁니다(`Canceled`). 만드는 순서는 ‘부스 실시간 대기 현황 → 켜는 순서’
2번에 있습니다.

## 문제가 생겼을 때

| 증상 | 확인할 곳 |
|---|---|
| “서버에 연결할 수 없습니다” | `assets/config.js` 값이 비었거나 `.gitignore` 에 걸렸는지 |
| 포털이 비어 있거나 “권한이 없습니다” | `migration-public-portal.sql` 실행 여부 |
| “필요한 표가 데이터베이스에 없습니다” | `migration-portal.sql` 실행 여부 |
| “해결 완료”·“업무 시작” 단추가 없음 | 운영진 로그인 전입니다 — 관리자 화면에서 로그인 |
| “해결 완료”·“업무 시작”이 안 됨 | `migration-fix-portal-actions.sql` · `migration-lock-portal-actions.sql` 실행 여부 |
| “담당 업무·운영 물품이 아직 준비되지 않았습니다” | `migration-operations.sql` 실행 여부 |
| 이틀 행사인데 날짜 탭이 없음 | 기본정보의 종료 일시가 둘째 날인지 · `migration-schedule-event-date.sql` 실행 여부 |
| “이미지 보관함이 아직 없습니다” | `migration-media-support.sql` 실행 여부 |
| 이미지 저장이 “요청 형식이 맞지 않습니다” | 같은 파일의 이미지 칼럼이 추가됐는지 |
| 관리자 로그인 후 “권한 없음” | `staff_profiles.role` 이 `admin` 인지 |
| 아이디로 “아이디 또는 비밀번호가 맞지 않습니다” | `config.js` 의 `adminIdDomain` 과 계정 이메일 도메인이 같은지 |
| 저장·삭제가 “0건” | 로그인 만료 → 재로그인 |
| 배포본만 옛 화면 | 운영 포털: GitHub Actions 의 `pages build and deployment` 실행 결과 · 부스 Live 사이트: Vercel Deployments 의 Production(`booth-live`) 배포 |
| 부스 Live 사이트가 안 바뀜 | 먼저 `booth-live` 에 push 했는지 봅니다(`main` 만 올리면 Vercel 은 미리 보기만 만들고 운영 주소는 그대로입니다) |
| (예비 · Netlify) 부스 Live 사이트 배포가 `Canceled` | 관람객 화면 · 운영자 화면과 관계없는 파일만 바뀌면 건너뛰는 것이 정상입니다. 바뀌어야 하는데 `Canceled` 면 Deploys → Trigger deploy → **Clear cache and deploy site**(캐시 없는 빌드는 건너뛰지 않음), 그래도 안 되면 빌드 훅으로 부릅니다(켜는 순서 2번) |
| (Vercel) 부스 Live 사이트 배포가 `Canceled` | 위와 같이 건너뛴 것입니다. 바뀌어야 하는데 건너뛰었으면 Deployments 에서 그 배포의 **Redeploy** 를 누르고 *Use project's Ignore Build Step* 을 끕니다(켜 둬도 같은 커밋을 다시 배포하면 건너뛰지 않습니다) |
| (Vercel) 빌드 로그에 `빌드 중단: ../assets/config.js 가 없습니다` | Root Directory 의 *Include files outside the root directory in the Build Step* 이 꺼져 있습니다. 켜고 다시 배포합니다(켜는 순서 2번) |
| (Vercel) 배포가 `Error` · Root Directory 가 없다고 나옴 | 그 브랜치에 `live/` 가 없는 것입니다(아직 `main` 에 합치기 전). Production Branch 를 `booth-live` 로 둡니다. 합치기 전까지 `main` push 의 미리 보기 배포는 계속 이렇게 끝나지만, 부스 Live 사이트 주소에는 영향이 없습니다 |
| 부스 Live 사이트 빌드 로그에 `빌드 중단: …` | 그 줄이 말하는 `assets/config.js` 값을 고칩니다(한 줄에 `이름: '값',` · 숫자는 계산식 없이 숫자 하나 · 공개용 키만 · `boothHelpLine` 은 작은따옴표 한 줄에 `'` 와 `\` 없이). 실패한 빌드는 올라가지 않고 앞 배포본이 그대로 남습니다 |
| 부스 Live 사이트 빌드 로그에 “운영 포털 흔적이 있습니다” | 바로 아래 찍힌 줄의 낱말(QR 인쇄 · 관리자 화면 이름, 운영 포털 주소, `adminIdDomain`)을 `visitor.html` · `booth-ctrl.html` · `assets/booth-core.js` · `assets/mock-data.js` · `assets/visitor.css` · `assets/booth-ctrl.css` · `boothHelpLine` 에서 뺍니다 |
| 부스 Live 사이트 빌드 로그에 “배포본에 없는 파일을 화면이 부릅니다” | 두 화면에 새 스크립트 · 스타일을 더했는데 배포본에 빠진 것입니다. 그 파일을 `live/build.sh` 의 복사 목록과 `live/netlify.toml` 의 `ignore` 목록에 같이 더합니다. `assets/` 밖의 파일이면 `live/vercel.json` 의 `ignoreCommand` 끝에도 더합니다(256자 안에서) |
| 인쇄 화면이 관람객용 · 운영자용 QR 을 만들지 않음 | `config.js` 의 `visitorSiteUrl` · `staffSiteUrl` 이 비었거나 https 부스 Live 사이트 주소가 아닌지(켜는 순서 3번). 둘이 같은 주소인 것은 정상입니다 |
| 관람객 화면에 행사 전 숫자가 안 뜸 | 정상입니다 — 운영 시간에만 보입니다(켜는 순서 6번) |

자세한 오류는 브라우저 개발자도구 콘솔에 `[portal]` · `[admin]` 으로 남습니다.
